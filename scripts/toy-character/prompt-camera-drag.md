# 依頼: ドラッグでカメラの横の角度を変えられるようにする（実装）

`src/demos/toy-figure/` のデモに、横のドラッグでカメラを回す操作を足します。設計は `.work/toy-character/camera-drag/design.md`（前回あなたが書いたもの）で、作者はこの設計で進めることに同意しました。設計に書いた動き（15〜50°、0.15°/px、8 px の境目、離した角度に留まる、慣性なし、押すと止まって見るのは残す、常に `touch-action: pan-y` で `touchGate` は使わない、左右キー 5°・Home で 30°、恐竜は角度が 0.3 秒動いていないときに画面の外から出す、`updateVisibility` で「歩き切った」と「見えている」を分ける、など）をそのまま実装してください。

最終回答は `-o` で受け取ります。ファイルへのリンクでなく本文そのものを書いてください。

## 設計から変えること・決まったこと

- 題名を「恐竜の野原を歩くフィギュア」に変える（`meta.ts` の `title`）。URL（`/toy-figure/`）は変えない
- `meta.ts`: `interaction: 'drag'`、`tags` に `'drag'` を足す。`description` は「おもちゃ風のキャラが恐竜のいる野原を歩き続ける。横にドラッグすると見る角度が変わり、押すと足を止めてそちらを眺める。」
- キャンバスの `aria-label` は題名に合わせて「恐竜の野原を歩くフィギュア」。操作の説明は `aria-describedby` で付ける（設計どおり）
- 画面の上の操作の案内: 設計では左上に短い案内を置くとしていましたが、ほかのデモに合わせるため、まず `docs/demo-guide.md` と、ドラッグで操作するほかのデモ（`meta.ts` が `interaction: 'drag'` のもの）が案内をどう出しているかを見て、それにそろえる。ほかのデモが案内を出していないなら出さない
- `docs/demo-guide.md` には、横だけで完結するドラッグは常に `pan-y` のままでよい、という 1〜2 行だけを足す
- `scripts/capture-previews.mjs` に `toy-figure` の `TUNE` を足す（設計どおり）。`public/previews/` には書かない。プレビューの撮り直しは呼び出し側がやる。試し撮りは `.work/` に出す
- `docs/toy-character/README.md` の決めたことの表は、呼び出し側が書くので触らない

## 今までどおり守ること

`scripts/toy-character/prompt-dino3.md` の冒頭にある守ること（キャラの歩き、歩き続けること、区間と原点の付け替え、押すと止まって見ること、動きを減らす設定、画面の外での停止、頭と体に物が重ならないこと）と、dino4・dino5 で作った恐竜の歩き（四足の前後の足を地面に留める、滑り、伸び率）と速さ（P95 16.7 ms 前後）は、30° のときに今と同じ値になること。30° で何も操作しないときの見た目は、今と同じにする（景色の置き方を変えたなら、30° の静止画を前と並べて差を書く）。

## 確かめること（画像と動画は自分で開いて見ること）

`.work/toy-character/camera-drag/` に出力する。開発サーバーは http://localhost:4410 （末尾の `/` が要る。止めない）。Playwright は Chrome（`channel: 'chrome'`、GPU）。

- `angles.png`: 1440×900（dpr 2）、800×500（dpr 2）、390×844（dpr 3）それぞれで、同じ歩きの姿勢の 15°・30°・50° を並べる。恐竜が見えている瞬間も 1 組
- `drag-desktop.webm`（1440×900）、`drag-mobile.webm`（390×844、タッチ）: 30 秒以上。往復のドラッグ、離したあと角度が留まること、離してから恐竜を押して止まって見ること、また歩き出すこと
- `iframe-scroll.webm`: 幅 800 と幅 390 の iframe を、縦に長い親ページ（別のオリジン）に入れ、タッチで横にドラッグして回ること、縦になぞると親ページがスクロールすること、横のドラッグで親ページが動いたり文字が選択されたりしないこと
- 3 分の記録を 15°・30°・50° に固定してそれぞれ: 前回と同じ項目に、恐竜 6 種それぞれの全身が画面に入っていた連続時間の最大、手前の物が頭と体を隠したフレーム数、区間の付け替えが画面の中で見えたフレーム数を足す
- ドラッグを続けながらの 3 分の記録（15〜50° を行き来する）: 景色が飛んだ回数、恐竜が画面の中で消えた・現れた回数
- 速さ（CPU throttling 4 倍、1440×900 と 390×844、ドラッグ中と止めたとき）。`pnpm build` のあとの `pnpm preview` でも測る
- E2E は設計どおり `e2e/toy-figure.spec.ts` と `e2e/motion.spec.ts` の `DRAG` に足す
- `pnpm verify` を通す（`.work/toy-character/walk/chrome.config.ts` を使ってよい）

## 決まり

前提が曖昧なところは妥当な仮定を置いて最後まで進め、置いた仮定は最終回答に書いてください。書き込むのは `src/demos/toy-figure/`、`e2e/toy-figure.spec.ts`、`e2e/motion.spec.ts`、`scripts/capture-previews.mjs`、`docs/demo-guide.md`、`scripts/toy-character/`、`.work/toy-character/` の中だけ。`src/shared/`、キャラの GLB、恐竜と景色の GLB は変えない。ブラウザの MCP は使わず、撮影と計測は Playwright のスクリプトで行う。コミットはしない。コードのコメントは、その行を見ただけでは分からない理由だけを短く書く。

## 最終回答

日本語で、結論から。実装した動き（数字つき）、設計から変えたところとその理由、景色の置き方を角度に合わせてどう変えたか、恐竜の出し方と退場の条件、15°・30°・50° の 3 分の記録の表、ドラッグを続けた記録、iframe とタッチの結果、速さ（開発と本番）、30° で前と変わっていないか、`pnpm verify` の結果、まだ足りないところ、置いた仮定。前置きと繰り返しは削る。
