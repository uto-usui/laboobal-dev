# 依頼: キャラの歩きを、恐竜の歩きと同じくらい滑らかにする（試し）

`src/demos/toy-figure/` のデモで、作者が「恐竜の動きは見直してすごく滑らかになったが、人間（キャラ）の歩きはカクカクした感じがする。同じように滑らかにできるか試してほしい」と言っています。今回は試しです。作者が前と後の動画を見比べて、採るかを決めます。

最終回答は `-o` で受け取ります。ファイルへのリンクでなく本文そのものを書いてください。

## 今の作り

- 恐竜は、Quaternius の Walk（作者がキーで付けたアニメーション）をそのまま再生し、接地中の足だけを IK で地面に留めている。体の進む速さは一定で、関節の動きは元の曲線のまま連続している
- キャラは `walk.ts` で、歩きを 1 歩ずつ手続きで作っている。一歩 140 mm・0.34 秒（`STEP_LENGTH`、`STEP_TIME`）。運ぶ足の太ももの角度は、1 歩の前半と後半をそれぞれ `smooth`（smoothstep）で `peak` とつないでいる（`walk.ts` の 460 行あたり）。骨は 20 本（root → spine.lower → spine.upper → spine.chest → neck → head と腕・脚）。決めたことの経緯は `docs/toy-character/README.md` の 2026-11-20 の行
- 呼び出し側の見当（確かめていない）: 1 歩ごとに smoothstep で区切っているため、歩の境目で関節の角速度がゼロに落ちて、止まっては動くように見えている。体の前進、上下、左右の揺れも、歩ごとに区切られて速度が途切れているかもしれない。腕や上半身が脚と同時に動いていて、遅れて付いてくる動きがない

## やること

1. カクカクの原因を数字で確かめる。30° のデモの画角と、横から寄った画角で、キャラの root と腰の前進速度・上下・左右、太もも・膝・足首・腕・背骨の角度と角速度を 1/120 秒ごとに記録し、時間のグラフにする。恐竜（たとえば Velociraptor か T-Rex の後ろ足）の同じ値と並べる。角速度が 0 に落ちる・跳ねる場所、加速度の不連続、描画のコマ落ちやフレームごとの位置の飛びがあるかを書く
2. 直し方を 2 つ以上試して比べる。たとえば:
   - A: 今の手続きのまま、1 歩ごとの区切りをやめ、歩きの位相を連続した周期として作る（関節の角度を周期関数やスプラインでつなぎ、角速度が歩の境目で途切れないようにする。腰の上下と左右、背骨のねじれ、腕の振りに位相の遅れと余韻を付ける）
   - B: CC0 の人型の歩きのアニメーション（Quaternius の Universal Animation Library など、ライセンスを確かめる。Mixamo のように CC0 でないものは使わない）を、キャラの 20 本の骨に移して再生し、恐竜と同じように接地中の足だけを IK で留める。キャラの GLB は書き換えず、歩きのアニメーションは別の小さなファイルか、読み込み時の対応表で持つ
   - ほかに良い方法があれば足してよい
3. いちばん良いものをデモに入れる。採らなかった案は `.work/` に動画と数字を残す

## 守ること

- 足が地面の上を滑らない（支える足の滑りは今と同じく 0 に近い）。膝は逆に曲がらない。2026-11-20 に確かめた範囲（太もも前後 25°、膝 60° まで）で服が裂けたり脚が食い込んだりしない
- 歩く速さは今と大きく変えない（一歩の長さと時間は、滑らかに見えるなら変えてよい。変えたら理由を書く）。キャラの画面の高さ、カメラ、景色、恐竜は変えない
- 押すと足をそろえて止まり、そちらを見てから歩き出す動き、動きを減らす設定、画面の外での停止、横のドラッグでの角度の変更は、今までどおり動くこと。止まる・歩き出すところも、カクッとならないこと
- 速さ: CPU を 4 倍遅くした条件で、フレーム時間の P95 が今（16.7 ms 前後）より悪くならない

## 確かめること（画像と動画は自分で開いて見ること）

`.work/toy-character/walk-smooth/` に出力する。開発サーバーは http://localhost:4410/toy-figure/ （末尾の `/` が要る。止めない）。Playwright は Chrome（`channel: 'chrome'`、GPU）。`?walk-inspect` の `window.__toyWalk` を使ってよい。

- `curves.png`: 上の 1 のグラフ。今のキャラ、採った案、恐竜を並べる
- `compare-side.webm`: 横から寄った同じ画角で、今の歩きと採った案を左右に並べた動画（10 秒以上。止まって見て歩き出すところを含める）。ほかの案も同じ撮り方で `option-*.webm`
- `compare-demo.webm`: 30° のデモの画角（1440×900、dpr 2）で、今と採った案を左右に並べた動画（20 秒以上）
- `legs-desktop.png`: 前回と同じ撮り方の、脚の連続写真（今と採った案の 2 段）
- 3 分の記録（30°）: 前回と同じ項目（膝の最小と最大、太ももの前後、足の上がり、支える足の滑り、靴底まわりの変形）に、関節の角加速度の最大と、角速度が 0 に落ちた回数を足す
- 速さ（CPU 4 倍遅く、1440×900 と 390×844）
- `pnpm verify` を通す（`.work/toy-character/walk/chrome.config.ts` を使ってよい）

## 決まり

前提が曖昧なところは妥当な仮定を置いて最後まで進め、置いた仮定は最終回答に書いてください。書き込むのは `src/demos/toy-figure/`、`e2e/toy-figure.spec.ts`、`scripts/toy-character/`、`.work/toy-character/` の中だけ。`src/shared/`、キャラの GLB、恐竜と景色の GLB は変えない。素材を新しく取り込むなら、配布元とライセンスを最終回答に書く。ブラウザの MCP は使わず、撮影と計測は Playwright のスクリプトで行う。コミットはしない。コードのコメントは、その行を見ただけでは分からない理由だけを短く書く。

## 最終回答

日本語で、結論から。カクカクの原因（数字つき）、試した案とそれぞれの結果、採った案と理由、3 分の記録の値（前と後）、速さ、守ることが守れているか、`pnpm verify` の結果、まだ足りないところ、置いた仮定。前置きと繰り返しは削る。
