# マウススクロールのイージングをカスタマイズする

## 何をしているか

寿司の絵文字を 1 つずつ置いた、画面の高さの帯が 10 枚縦に並んでいる。ホイールを回すと、ページはすぐには止まらず、少し遅れてすうっと追いついて止まる。

## 大事なところ

中身を画面に貼り付けて（`position: fixed`）、`translateY` で動かすことで、スクロールしているように見せる。動かす量は、スクロールの位置にすぐ合わせず、毎フレーム「差の一部だけ」近づける。差が大きいうちは速く、近づくほどゆっくりになるので、イージングを付けたような止まり方になる。近づく割合を変えると、止まり方の重さが変わる。

もとは 1 フレームに差の 8% だけ近づけていた。ここでは `damp()`（src/shared/math.ts）で、60fps のときに同じ 8% になる速さにしている。フレームレートが違っても、同じ時間で追いつく。

## 作り方

スクロールそのものはブラウザに任せている。中身を画面に貼り付けると、ページの高さがなくなってスクロールできなくなるので、外の箱に中身と同じ高さを持たせる。ページは今までどおりスクロールし、`scrollY` が変わる。`loop()` で毎フレーム、見た目の位置をその `scrollY` へ近づけ、`translate3d(0, -位置, 0)` を入れる。

ホイールのイベントは止めない。キーやスクロールバー、ページの中の検索でも同じように動く。ページの端まで来たら、記事の iframe の外のページへ、そのままスクロールが渡る。

動きを減らす設定のときは、中身を貼り付けるのをやめて、ふつうのスクロールにする（src/shared/motion.ts の決まりの 4）。指で動かす端末でも外す。指のスクロールにはもともと慣性があり、さらに遅らせると、指と絵がずれるため。

## もとのデモから変えたこと

記事の本文にはコードがない。fiddle との違いは次のとおり。

- fiddle は SmoothScroll 1.4 を読んでいたが、動きは自前のコードで作っていた。SmoothScroll を読むのをやめた
- もとは `body { overflow: hidden }` でページのスクロールを止め、ホイールを `preventDefault` して、ホイールの量を自分で足していた。キーや指ではスクロールできず、記事の iframe の上ではホイールで記事を読み進められなかった。ここではページをふつうにスクロールさせ、その位置に見た目を遅れて合わせる形にした。ホイールを奪わない
- 1 フレームに差の 8% 近づけるのを、`damp()` で時間に合わせた
- 差が 0.1px より小さくなったら、ぴったり合わせて止める。もとは上の端だけを丸めていた
- `mousewheel` と `DOMMouseScroll` の切り替えをやめた（ホイールのイベントを使わなくなった）
- `-webkit-` などの付いた `transform` を外した
- 動きを減らす設定と、指で動かす端末では、ふつうのスクロールにする
