# 風のあとに揺れる葉

## 何をしているか

秋のアスペンの小枝に付いた葉が、横になぞる手の速さと向きに応じた風を受ける。強くなぞると葉が裏返り、逆になぞるとそのときの角速度に応じて揺れが強まったり弱まったりする。幅600px未満では三枚、それ以上では六枚を描く。葉柄の硬さと慣性が異なるため、風がやんでも違う周期で揺れ戻る。

## 読み込むたびの違いと秋色

乱数種はページを開くたびに作り、同じページ内のリサイズと設定変更では保つ。小枝の構図を保ちながら、付け根の位置を±0.12、奥行きを±0.1、葉柄の長さを±22%、葉身の長さを±17%、幅を±18%変える。静止角は傾きを±0.28rad、ねじれを±0.48rad、画面内の向きを±0.32rad変え、輪郭の丸みと先細りも変える。表示前に接触の拘束を解き、安全な配置だけ採用する。解けない場合も最初の16候補は振れ幅を保って別の乱数種を試し、その後だけ縮める。最初から同じ配置へ近づけて変化を消さないため。

六枚の色は金三枚、黄緑一枚、橙一枚、褐色一枚にする。見切れやすい右上の六枚目を金にし、残り五枚の配色を入れ替える。狭い画面では金・黄緑・橙または褐色の三枚にする。派手な赤は使わない。葉の中心と葉脈沿いには緑を残し、縁は橙がかった色にする。葉脈の暗い線だけを緑にするのではなく、その周囲にも緑が残るようになめらかに広げる。細かい褐色の斑点や法線のノイズは使わない。

逆光の基準となる金色はsRGBの #E9B93A に近い色。Beer–Lambertの法則を近似した透過光を使い、葉脈では厚さと吸収を増す。背景と透過光は同じ画面座標の空の抜けと四つの玉ぼけを参照する。明るい場所で透過色を黄色へ寄せる割合を最大12%に抑え、葉ごとの秋色を残す。影は1024×1024の深度から九点を採ってぼかす。実物の材料定数に基づく再現ではなく、接写の見え方のための近似。

## 操作と自動の風

横になぞる速さを符号付きの風速にし、風圧からトルクへ変換する。風速の上限は±3.5。左右の矢印キーでも、その方向へ幅のある短い風を送れる。触り始めると見本の突風を消し、操作中と終了後4秒は自動の風もそよ風も止める。慣性は消さない。触っていないときは約10.5秒ごとに見本の風が横切る。

案内は左下の一行、設定は最初は閉じる。タッチは共有のtouchGateを使い、横方向に動かし始めた操作だけを風として受け取る。CSSのtouch-actionはpan-y。動きを減らす設定では自走するループを止め、入力のときだけ最大四歩進めて描き直す。画面外と非表示タブでも共有のループが止まる。

## 物理と接触

葉柄の傾き二軸、ねじれ、葉身のたわみをCPUで解く。角ばね、重力、相対風速と葉面の向きから求める風圧、角速度に比例する減衰を使う。慣性は0.8〜1.6、ばね定数は8.2〜16、標準の減衰係数は0.68。1/120秒の固定刻みで半陰的Euler積分を行う。通常の一フレームの上限は二歩で、追いつけない時間を捨てる。

描画する葉面は72×24区画の三角形。接触では少ない頂点から作った凸包を使い、細かい描画頂点との差と、たわみの差を半径に足す。区画内の全頂点で誤差を求めるため、描画の三角形の内部も包まれる。葉柄は三次ベジェ曲線の四つの制御点の凸包に管の半径を足す。分離軸を前の更新から再利用し、遠い組を先に外す。近い組だけGJKで調べ、最大12回で安全を証明できない場合は安全扱いにしない。支持点は葉の座標で検索し、全頂点を毎回世界座標へ写す割り当てを避ける。

距離拘束の位置補正は最大二回。葉面の姿勢の勾配は回転軸から直接求め、葉柄だけ差分を使う。接近速度だけを除き、反発と摩擦は加えない。葉面どうしは0.008、葉柄と葉面は管の半径に0.005、葉柄どうしは半径の和に0.002を足した距離を保つ。位置補正には0.012の余白を足す。

更新の両端を包む凸包を、回転・たわみ・葉柄の制御点の曲がりによる誤差分だけ広げ、途中の突き抜けも調べる。安全を証明できない区間だけ最大二段に分け、それでも不明なら手前で止める。一組の接触で遠い葉まで止まり続けるときは、一枚ずつ固定した順で動かし、それぞれを再び掃引して採用する。自分の葉柄との接触は描画三角形まで降りる木とカプセルで調べる。接合部の葉柄の最後の二区間と葉面の最初の二行だけは重ねる。

小枝との距離は、葉面の全描画頂点を包む48区画、葉柄のカプセル、小枝の112本のカプセルから下限を求める。小枝を包む木で遠い区間をまとめて外す。同じ姿勢の距離を再利用し、途中の姿勢を最大二段に分ける。余白0.016を目安に安全な所で止め、接近速度を除く。距離の下限が切り替わる場所で反発ばねが静止中の葉に力を加え続けることを避ける。小枝は右上から左下へ伸びる一本の管で、節と樹皮の凹凸を残す。葉柄の根元は描画する枝の三角形上に固定する。

## 描画と代替表示

WebGPUで曲面、表裏の色、透過光、影を描く。輪郭は4サンプルのMSAAで整える。背景の樹冠、六本の幹、空の抜け、玉ぼけは手続き的に描く。動かない背景はリサイズ時だけrgba16floatのテクスチャに描き、毎フレームはその絵を読む。光の明るさは合成時に掛けるため、設定の変更にも追随する。WebGPUが使えないときとdeviceを失ったときは、同じ乱数種の配置・輪郭・秋色によるSVGと一行の案内を表示する。GPUのエラーはコンソールとstatusに残す。

uniformは行列二つとf32四つで144バイト。葉はvec4f八つで一枚128バイト、最大六枚で768バイト。group 0のbinding 0がuniform、1が葉のstorage。group 1のbinding 0が深度テクスチャ、1が比較sampler。group 2のbinding 0が背景のテクスチャ、1が線形補間sampler。深度と背景の事前描画のパイプラインはgroup 0だけを使う。追加のshapeは丸み、先細り、緑の残り方、縁の色づきの四値。

## 確かめ方

`node src/demos/nature-aspen/verify.mjs` で64組の初期配置を独立した描画三角形の検査と照合する。通常幅と狭い幅を最小減衰0.5・最大風速±3.5で各7,200歩進め、更新後と途中の三姿勢の距離を検査する。短い強風、連続風、逆風、左右交互の入力、自動の風、最後の20秒の無風を含む。裏返り、揺れ戻り、無風時の震え、更新順の差も検査する。凸包の判定では、更新の両端が離れていても途中で面を横切る例を検査する。

ブラウザの計測はURLに `?measure` を付けると有効になる。Performance Timelineの `aspen-physics` は、描画前に実行した物理更新全てを一フレーム分として記録する。数値検証の一歩の時間と、ブラウザの一フレーム分を区別する。

11回目の修正では64組の初期配置と14,400歩の検証が通った。小枝との余白は更新後・途中とも最小0.015991、一歩の角度変化は最大0.06787rad、ねじれは最大1.98985rad。無風時の変化は最大0.0002241rad、更新順の差は0だった。通常幅と狭い幅の両方で短い強風による裏返りと揺れ戻りを確認した。Nodeでの一歩の計測は中央値1.50ms、95パーセンタイル8.25ms。通常のブラウザ操作と違い、最小減衰で長時間最大風を加える検証を含む。

AppleのMetal 3アダプターを使う専用のヘッドレスブラウザで、1280×800の読み込み後3秒待ってから横ドラッグ約3秒を計測した。背景の再利用後は約59.1fps、フレーム間隔の95パーセンタイル16.7ms、最大33.4ms。物理更新一フレーム分は中央値2.5ms、95パーセンタイル4.2ms、最大5.8msだった。物理4msの目安をわずかに超えるため、全ての配置と端末で60fpsを保証する記録ではない。二度の読み込みを撮影し、葉の向き・寸法・輪郭と配色の違いを見比べた。WGSLは公式の予約語146語との衝突がなく、実ブラウザで八つの描画パイプラインを作成し、canvasの描画を確認した。
