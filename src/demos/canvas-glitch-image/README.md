# 震えて崩れる写真

## 何をしているか

写真をいつも細かく震わせ、3 秒に 1 回、ほんの一瞬だけ大きく崩す。色が左右に分かれ、横の筋が走り、四角いブロックが入れ替わり、砂嵐が強くなる。

## 大事なところ

崩れ方の強さ（`strength`）を 1 つの値にまとめ、すべてのノイズがそれを見ている。強さは 3 秒ごとに 1 へ跳ね、0.15 秒（周期の 5%）かけて 0 へ戻り、残りはずっと 0。ふだんは弱く震え、たまに一気に崩れるという緩急が、壊れかけの映像らしさになる。いつも強く崩れていると、ただのノイズの模様に見えて目が慣れてしまう。

ノイズは役割の違うものを重ねる。

- 横の走査線: 縦の位置ごとにノイズで横へずらす。細かいびりびり（時間を 400 倍で回す）、たまに走る太い線（`step(0.9999, sin(...))` でほとんどの場所を 0 にする）、ゆっくり下りる線の 3 つを足す
- 色の分かれ: 赤と青を逆向きにずらし、緑はそのまま。強さが 0 のときも少しだけ揺らしておく
- ブロック: 時間を `floor` で区切ってからノイズに入れる。なめらかに動かさず、数十ミリ秒ごとにぱっと入れ替わるので、データが欠けたように見える。縦と横のノイズを掛けて、四角い形にする
- 砂嵐と、下ほど白く浮かせる明るさ

ずれの量は px で考えて、最後に画面の幅で割って uv にしている。画面の大きさが変わっても、線の太さやずれ方が同じに見える。

## 作り方

three の `ShaderMaterial` で、画面いっぱいの板を 1 枚描く。ノイズは共有の `simplex-noise.glsl` の `snoise(vec3)` を使い、シェーダーの文字列の先頭に足している。ブロックや走査線で横へずらした先が写真の外に出たら、端で折り返して読む。

時間は 10 分で 0 に戻している。シェーダーの中に時間の 2 乗を使う式があり、何時間も開いたままにすると値が大きくなりすぎるため。10 分は 3 秒の周期の倍数なので、戻したときに周期がずれない。

## もとのデモから変えたこと

- 旧デモは写真をいったん別の描画先に描き、それを読み直して崩していた。1 回で描けるので、写真を直に読むようにした（画面に貼るときの切り取りは、シェーダーの中で読むたびにする）
- 写真は旧デモと同じ Unsplash の写真（photo-1547962041-6d2d7c4bdf6e）を落として置いた
- 文字が震えるグリッチ（webmanab の lab の記事。デモは 2026-11-04 に下げた。docs/history/dropped/B3.md）とは別物として残した。あちらは DOM の文字を CSS の transform で震わせるもの（codrops の glitchFx）で、こちらは写真を GLSL で崩すもの
