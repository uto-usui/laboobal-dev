# スクロールで色を変える

## 何をしているか

スクロールすると、箱が下から上へ通り過ぎながら、緑から水色、青へと色を変える。上へ行くほど明るくなる。

## 大事なところ

色は、箱が画面のどこまで来たか（進み具合、0〜1）から決めている。進み具合の考え方は scroll-reveal と同じで、箱の上端が画面の下から 100px 入ったところで 0、箱の下端が画面の上を出たところで 1。

進み具合 p を、色相と明るさに写す。

- 色相: 110（緑）から 240（青）へ。130 度ぶん回すので、途中で水色を通る
- 明るさ: 45% から 70% へ
- 鮮やかさ: 75% のまま

2 つの色を混ぜるのではなく、色相を回している。混ぜると緑と青の間はくすんだ色になるが、色相を回すと、途中の水色もはっきりした色のまま通る。

このデモは CSS だけで動かしている。CSS の scroll-driven animations（`animation-timeline: view()`）は、要素が画面に入ってから出るまでを、アニメーションの 0% から 100% に当てる。scroll-reveal で JS で計算していた進み具合を、ブラウザが計算してくれる。

- `animation-range: cover 100px cover 100%` で、0% を「画面に入って 100px のところ」、100% を「画面から出きったところ」にする。scroll-reveal の offset と同じ
- アニメーションで動かすのは `--p` という数だけ。`@property` で数として登録しておくと、0 と 1 の間の値もアニメーションで取れる
- 色は `hsl(calc(110 + 130 * var(--p)) …)` で、`--p` から計算する

色そのものを `@keyframes` で動かすと、ブラウザが 2 色の間を混ぜてしまう（くすむ）。`--p` だけを動かして色の式に入れると、色相を回す動きをそのまま書ける。

## 作り方

`animation-timeline: view()` と `@property` で書いている。スクロールのたびに JS を動かさないので、メインスレッドが忙しくてもなめらかに動く。

scroll-driven animations に対応していないブラウザでは、`@supports` で外したうえで、JS（`src/shared/a/view-progress.ts`）で同じ `--p` を入れる。`@supports` で外しておかないと、時間で動くふつうのアニメーションとして一瞬で終わり、`--p` が 1 のまま止まる。

ライブラリ（locomotive-scroll や Lenis）は使っていない。スクロール量に合わせて色を変えるだけで、慣性のあるスクロールのような、ライブラリならではの動きは要らないため。

## もとのデモから変えたこと

- 旧デモは JS で毎フレーム進み具合を計算し、chroma-js で HSL の色を混ぜていた。CSS の scroll-driven animations と `hsl()` の計算にした。色の変わり方は同じ（色相と明るさを、進み具合の割合で動かす）
- 開いたときに箱が画面の下の方に少し見えるよう、上の余白を減らした
- 背景をサイトの暗い色にした
