# 真ん中から広がる波

## 何をしているか

10 × 10 のマス目を斜め上から見下ろす角度に倒し、真ん中のマスから順に浮き上がらせ、また沈める。波紋のように外へ広がる。

## 大事なところ

GSAP の `stagger` に `grid: [10, 10]` と `from: 'center'` を渡すと、マスの格子の位置から真ん中までの距離を出し、その順に始まりを遅らせてくれる。並び順（1 列目、2 列目…）ではなく距離の順なので、四角い列ではなく丸い輪のように広がる。

`amount: 1` で、100 個の遅れを全部合わせて 1 秒に収めている。1 個あたりの遅れ（`each`）で書くと、マスを増やすほど波が遅くなる。`amount` なら、マスの数を変えても、波が端に届くまでの時間は同じ。

ease は `back.inOut(4)`。動き出す前に一度反対側へ沈み、行きすぎてから戻る。4 は強めで、波の頭が跳ねて見える。`repeat` と `yoyo` を `stagger` の中ではなく外に書いているので、くり返すのはマス 1 つずつではなく 100 個の波全体になる。全体を逆に再生するので、戻りは最後に浮いた外側のマスから沈み、波が外から真ん中へ寄せてくる。真ん中のマスは浮いたまま外の波を待ち、最後に沈む。広がる波と寄せる波が交互に来て、間に `repeatDelay` で 0.2 秒休む。マスごとに行き来させたいなら、`repeat` と `yoyo` を `stagger` の中に書く（そのときは戻りも真ん中から沈む）。

浮き上がりは z（画面の奥行き）で出している。格子を `rotateX(60deg) rotateY(30deg)` で倒してあるので、z の動きが斜め上への盛り上がりに見える。同時に少し縮める（0.75 倍）ので、マスの間がひらいて、どのマスが動いているかが分かる。

## 作り方

GSAP では CSS の変数 `--lift` を 0 から 1 へ動かすだけにしている。浮き上がる高さ（入れ物の高さの 20%）、縮み方、色は CSS で `--lift` から計算する。高さを入れ物の大きさの単位（`cqh`）で書けるので、iframe の大きさが変わっても tween を作り直さなくてよい。

浮いたマスほど少し明るくした（`color-mix` で白を最大 25%）。`back` の ease で `--lift` が 0 を下回ると混ぜる割合が負になるが、`calc` の結果は 0% に丸められるので、そのままでよい（Chrome で確かめた）。

## もとのデモから変えたこと

- 旧デモは GSAP で `z: 100` と `scale: 0.75` を直接動かしていた。`--lift` 1 つにまとめ、高さを入れ物の高さの割合にした
- perspective と格子の奥への下げ幅（どちらも 800px）を、入れ物の高さの 1.6 倍にした。高さ 500px のときに旧デモと同じ
- 浮いたマスを少し明るくした。旧デモは 1 色で、どのマスが浮いているかが形でしか分からなかった
