# イワシの群れ

## 何をしているか

青い海の中を、丸い塊になった 8,192 匹のイワシが泳ぐ。曲がると横腹が銀色に光り、群れの中を光の帯が走る。ブリやカツオを思わせる捕食魚が、群れの縁にある小さな塊を狙い、突っ込んで抜け、大きく回って戻る。左下で「自動」と「自分で動かす」を切り替えられる。最初は自動。

クリックやタップで水を叩くと、その場所から一瞬強く押されて広がり、またまとまる。この操作は両方のモードで残す。イワシの色、反射、数、近い 7 匹に合わせる泳ぎは共通。

## 大事なところ

ふだん光るタイミングは個体ごとの時計ではなく、横腹と光と視線の向きで決まる。曲がると体が傾き、その向きが近い 7 匹へ伝わることで、隣り合う魚が続けて光る。体長 1 の紡錘形の胴と二股の尾を描いて、1 匹ずつの形を残している。

おびえも近い 7 匹へ渡す。反応した直後の魚から受け取り、約 0.1 秒待って反応する。捕食魚や水を叩く刺激を直接受けた魚から信号を出し、次へ渡す強さは発火時の値を保って、伝達のたびに少しずつ弱める。反応してから 0.28 秒の間だけ横腹を返し、銀色を薄く足して波の前縁を見せる。1.5 秒は再反応させず、残ったおびえを送り合って光り続けるのを防ぐ。

おびえると速く泳ぎ、そろえる力と寄る力を強める。群れの空間の縁だけで引き戻し、中心へ引く力で 1 点に潰れるのを防ぐ。7 匹に合わせる仕組みや伝達の待ち時間は表現上の仮定で、イワシの行動の厳密な再現ではない。

## 操作と設定

「自動」では、群れ全体から等間隔に 256 匹を観察する。その近所に 3 匹以上いる縁の塊を候補にし、群れの中心からの距離、近所の少なさ、捕食魚からの距離と向きで選ぶ。塊の平均速度を使って進路を予測する pursue、目標へ向かう seek、近くで減速する arrive、回り込みの目標を揺らす wander を組み合わせる。ゆっくり接近し、突進したら出口まで抜け、減速して大回りする。中心へ直線を往復する軌道は使わない。

「自分で動かす」では、カーソルや指を群れの中央の奥行きへ投影した位置を目標にする。どちらのモードも加速度は最大 13、旋回は最大 1.05 rad/s に制限し、横向きの加速も同じ加速度の範囲に収める。切り替えても位置や速度は引き継ぐ。目標が止まれば減速して近づき、指を離したあとも最後の目標を保持する。群れを押しのけるのは捕食魚の実際の胴の前後を結ぶ線分で、画面から奥へ伸びる視線ではない。

ボタンは Tab で移動し、Enter・Space で切り替えられる。左右矢印と Home・End でも選べる。選択中は下線と `aria-pressed` で示す。案内は左 16px・下 14px、12px、白の 60%。狭い画面では折り返す。

クリックやタップは、群れの中央の奥行きへ投影した場所を叩く。群れの半径に合わせた球状の範囲に、0.35 秒で消える強い押し返しを入れる。捕食魚は消さない。縦になぞったときは記事のスクロールに渡す。指の引っぱりやカメラ回転は加えない。操作中と最後の操作から 5 秒間は背景の光とカメラの移動を止める。

設定は最初は閉じる。魚の数はさらに閉じた「描画」の中に置き、4,096 / 8,192 / 16,384 匹から選ぶ。既定は端末によらず 8,192 匹。

動きを減らす設定では、600 歩ならしてから捕食魚も含めて 1 枚描いて止める。途中で設定を切り替えたときは、その場で止める。背景、カメラ、尾のしなり、捕食魚、イワシをすべて止め、カーソルやクリックでも再開しない。モードの選択はできる。

## 作り方

WebGPU の compute で升に並べて近所を探し、1/60 秒ずつ進める。半径は (20, 13, 16) に匹数と 16,384 の比の立方根を掛ける。格子は 70×50×60 升、1 升は 1.2 で、最大数の群れにも余白を取る。索引は 32,768 個の桶へハッシュし、魚の番号の連結リストを compute 1 回で作る。空の升の累積和や並べ替えは行わない。同じ桶に入った別の升の魚は、升の座標で区別して近所から外す。桶ごとに個数の固定枠を設けず、密な場所でもあふれさせない。まわりの 27 升を見る順序、最大 256 匹を見る制限、近い 7 匹を選ぶ規則は共通。

魚の状態は位置とおびえ、速度と傾き、伝達の待ち時間ときらめきと再反応の待ち時間と次へ渡す強さの 3 つの vec4（48 バイト）。格子にも同じ stride を渡す。uniform は TypeScript の項目定義から WGSL と書き込み位置を生成する。

イワシの描画は魚ごとに 4 頂点の四角 1 枚を使い、横腹が映す水面の明るさで反射を決める。投影、傾き、反射、霞は compute で個体ごとに一度だけ求め、四隅で共有する。描画用の状態は 80 バイトで、3 つの vec4（中心・前方・背の投影）、被覆率・反射・霞・個体差の vec4、きらめきと詰め物を持つ。色と反射の式は変えない。色が違う魚どうしの前後は深度バッファで決める。4 サンプルの MSAA と alphaToCoverage で輪郭をなめらかにし、1px 未満になる魚は大きさを保って被覆率を下げる。水の背景はグラデーション、水面の帯、弱い光の筋で描き、遠い魚は水の色へ寄せる。滑らかな背景だけは縦横 1/4 のテクスチャに描いて線形補間し、微細な粒は出力解像度で足す。背景の時計が止まる操作中はそのテクスチャを再利用する。イワシの解像度、色、反射、MSAA のサンプル数は落とさない。

捕食魚の全長は約 7（イワシの約 7 倍）。胴は 40×24 の断面から立体のメッシュを作り、後端には細い尾柄の断面を残す。尾柄へ重なる根元から、深い二叉の三日月形の尾びれを張る。背びれと尻びれの後ろには、それぞれ 4 個の小離鰭を並べる。

ひれは少しふくらんだ薄い膜で、付け根を胴の内側に重ねる。根元の色から水面の透過光を含む色へ移り、先へ行くほど被覆率を下げる。細い鰭条を数本入れ、胸びれの先は泳ぎの位相に合わせてわずかに動かす。透け方は 4 サンプルの alphaToCoverage で表し、背後のイワシとの前後も深度で決める。特定の魚種のひれの枚数や形を厳密に再現するものではない。

背は暗い青、腹は銀白にし、断面の法線で照明と水面の反射を計算する。後ろ半分を進行する波でしならせ、旋回の曲率で胴全体を曲げる。尾柄と尾びれにも同じ変形を使い、つなぎ目が離れないようにする。法線は変形の解析的な微分で補正する。共有する頂点を index で参照し、メッシュは起動時に一度だけ GPU へ送る。頂点は位置・法線・材質・膜の座標・胸びれの動きの重みの 10 floats（40 バイト）。霞はイワシと同じ距離の指数減衰と、画面の深さに応じた水の色で受ける。

捕食魚の操舵は CPU で行う。0.6 秒ごとに、群れから等間隔に選んだ 256 匹だけを compute で詰め、12KiB を非同期で読み戻す。読み戻しを描画ループで待たず、魚の数を変えたときの古い読み戻しは捨てる。候補ごとに近所の配列を作らず、距離の二乗で数えてから、選んだ塊の平均だけを求める。捕食魚を無効にしたときは描画、操舵、観察を省く。イワシの状態の配置、操舵の係数、色と反射の式は変えない。

ポインターイベントでは最後の画面座標だけを持ち、座標の変換と目標への投影は描画フレームに一度までにする。背景の時計と画面サイズが同じならカメラ行列も再利用し、uniform の送信は描画フレームに一度にまとめる。
