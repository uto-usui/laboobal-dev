# スクロールの進み具合を数える

## 何をしているか

スクロールすると、緑の箱が下から上へ通り過ぎていく。箱の中に、箱が画面のどこまで来たかを 0〜1 の数で出している。下の細い線も同じ数で伸びる。scroll-reveal-color と scroll-reveal-transform は、この数を色や形に使ったもの。

## 大事なところ

スクロールで何かを動かすときに、まず要るのは「要素が画面に入ってから出るまでの、どのあたりにいるか」を 0〜1 の数にすること。数にしてしまえば、色でも位置でも回転でも、0〜1 を好きな範囲に写すだけで動かせる。

0 と 1 をどこに置くかを決める。

- 0: 要素の上端が、画面の下端から offset だけ入ったところ
- 1: 要素の下端が、画面の上端から出たところ

この間を要素が進む距離は「画面の高さ - offset + 要素の高さ」。いまの位置から進んだ距離をこれで割ると、進み具合になる。

```
進み具合 = (画面の高さ - offset - 要素の上端の位置) / (画面の高さ - offset + 要素の高さ)
```

要素の上端の位置は、画面の上を 0 とした位置（`getBoundingClientRect().top`）。スクロールすると小さくなっていくので、進み具合は増えていく。

offset は「どこから数え始めるか」。このデモは 100px で、箱が画面の下から 100px 見えたところで 0 になる。下端に入った瞬間から動かすと、見えるか見えないかのところで動きが始まってしまうので、少し見えてから始めている。マイナスにすると、画面に入る前から数え始める（scroll-reveal-transform は -150px）。

このデモでは表示を 0〜1 に丸めているが、計算した数は範囲の外にも出る。画面に入る前はマイナス、出たあとは 1 より大きい。

## 作り方

`scroll` のイベントで進み具合を計算し、数と線を書き直している。計算は `src/shared/a/view-progress.ts` にあり、scroll の 3 本で共通。

ライブラリ（locomotive-scroll や Lenis）は使っていない。慣性のあるスクロールや、要素の固定のような、ライブラリならではの動きがないため。

ページそのものをスクロールさせている（記事に iframe で埋めたときも、iframe の中がスクロールする）。開いたときに箱が画面の下の方に少し見えるよう、上に画面 4 分の 3 ほどの余白を置いている。

## もとのデモから変えたこと

- 旧デモは requestAnimationFrame で毎フレームスクロール量を読みに行っていた。`scroll` のイベントで読むようにした
- 旧デモは要素の位置を最初に 1 回だけ測り、スクロール量から計算していた。毎回 `getBoundingClientRect()` で今の位置を測るようにした。読み込みのあとで上の高さが変わっても、ずれない
- 数だけでなく、下に線も出すようにした
- 背景をサイトの暗い色にした
