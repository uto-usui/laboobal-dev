# 風にほどける綿毛

## 何をしているか

低い日が差す、ぼけた野原を背景に、逆光に透けたタンポポの種が風に乗る。綿毛のそばでカーソルや指を動かすと、移動の速さと向きがその場所の空気に伝わる。外れた種はその流れを受け、傘を上、茶色い種を下にして漂う。別の向きからなぞれば、すでに飛んでいる種のまわりの流れも変わる。

The Nature of Code 4 章の粒子系（外す、漂わせる、入れ替える）に、格子の流体と、向きで変わる空気抵抗を足したデモ。物理量は見た目のための相対単位で、実物の飛距離や風速の計測には使わない。

## 大事なところ

頭は一つだけで、画面の高さの約 3 割を使う。72 本の種、1 本あたり 64 本の毛、飛行中の上限 20 本はそのままにする。初めの一枚には頭に残る 68 本と飛び立った見本の 4 本を置く。カーソルが入るか指が触れたら、飛行中の見本だけを頭へ戻し、以後は自分の息で外した種を追えるようにする。操作によって飛ばした種は戻さない。見本が動いているところへ入ったときは、その流体の速度もゼロにして、息から新しい流れを作る。

画面にカーソルや指がある間と、離れてから 4 秒間は、自動放出と野原の風の追加を止める。残っている流体は移流・減衰を続けるため、操作をやめたあとも吹いた流れの余韻がある。未操作の見本では 0.45〜1.65 秒おきに 1 本ずつ放出する。風の設定がゼロなら自動放出もしない。息で外す本数は頭からの距離、移動距離、CSS px/秒の速さで決め、描画と同じ奥行きの投影で、なぞった線分から距離 0.14 以内の種を近い順に外す。短い移動の端数も積み上げ、速くなぞるほど多く外す。CPU は付着を外すだけで、息を種の初速や加速度へ直接足さない。

冠毛の傘、細い柄、先に付く重い種を一続きに見せる。高さ 400〜500px の入れ物で、合焦面の種は柄を含めて約 40〜55px、手前の種は約 60〜80px を目安にする。画面奥の右上に低い日の暖かいにじみを置き、毛と茎の右縁に逆光を通す。背景の色、光源、飛行中の毛の明るさ、ぼけの設定は保つ。

## 風と種の計算

WebGPU の compute で 40×24×12 の三次元流体を解く。速度は各セルの正側の面、圧力はセルの中心に置く staggered grid を使う。計算領域は x=-4〜4、y=-1.6〜2.4、z=-2〜4。格子幅は軸ごとに異なるので、発散・圧力・勾配にそれぞれの幅を使う。

1. 前の速度を周囲 8 点から三線形補間し、流れを中点から逆にたどる semi-Lagrangian 法で速度を移流する。
2. カーソルや指の位置を z=0 の息の中心と仮定し、移動方向の速度を局所的に流体へ入れる。本数に使う入力の強さは CSS px/秒の速さを 600 で割り、最大 2.4 にして設定の「息の強さ」を掛ける。流体へ渡す目標速度は同じ速さを 4800 で割って設定を掛け、奥行きへの速度（入力の強さの 0.02 倍）と合わせたベクトルの長さを最大 0.60 にする。本数の増え方を保ちながら、流される速さを抑えるためである。影響は画面方向の幅 0.25、奥行き方向の幅 0.42 のガウス分布で弱め、毎秒 42 の係数で目標速度へ近づける。縦長でも横長でも同じ操作速度を基準にし、40px/秒未満の移動や静止したカーソルからは入力しない。未操作のときだけ、空間的に変化する弱い回転を持つ野原の風を外力として加え、流体の速度には弱い減衰を掛ける。
3. 面の速度差から発散を求め、圧力の Poisson 方程式をヤコビ法 36 回で近似する。圧力勾配を引いて発散を減らす。境界を通る速度はゼロ、外側の圧力差もゼロとする。有限回の反復なので厳密な非圧縮解ではない。
4. 外れた種の初速を、その位置で補間した流体の速度から作り、長さを最大 0.18 にする。飛行中に種が受け取る流体の速度も最大 0.20 にして、その速度との差から空気抵抗を求め、重力と合わせて積分する。積分後の種の速度には最大 0.24 の制限も置く。いずれも各成分ではなくベクトル全体の長さを制限し、流れる向きを保つ。見本の初速 0.10〜0.22 の数倍以内に収めるための値で、`flight.ts` から入力処理と WGSL に渡す。種へ直接加えるカーソルの力や、種ごとの人工的な奥行きの流れは使わない。局所的な息を射影してできる回り込みと、その移流が種へ伝わる。

以前は通常の息の目標速度だけで約 4.7 になり、放出時の初速も空気抵抗で追い付く速度も無制限だった。1280×800 で 380px を 450ms・30 段で横になぞる数値再現では、外れた 7 本が操作終了 0.3 秒後に速さ 2.82〜3.58 で右端付近に達し、1 秒後には全て画面外へ出た。位置は有限だった。初速だけを下げても流体で再加速するため、入力・初速・追従する流速・積分後の速度のそれぞれを抑えている。

速度は 2 枚の vec4 バッファで移流前後を分け、圧力は 2 枚の f32 バッファを交互に使う。発散にも f32 のバッファを使う。流体は描画時に、そのフレームで進んだ固定刻みの合計だけ進める（最大 8/120 秒）。圧力は毎回ゼロから解き、描画だけの dt=0 では流体を更新しない。

種は位置と年齢、速度と状態、姿勢と回転角、角速度の 4 個の vec4 を持つ。2 枚の storage buffer を交互に使い、1/120 秒の固定刻み、1 フレーム最大 8 歩で力と姿勢を積分する。放出時は、球面に沿った付着姿勢を傘が上の姿勢へ切り替え、左右と奥行きには根元の向きの 0.3 倍の傾きを残す。空気抵抗は傘の軸方向を横方向より強くし、重心が下にある種の復元力と回転の減衰を組み合わせる。復元先には約 ±19° の個体差と振幅約 9° の揺れを残す。軸回りの回転は毎秒 0.12〜0.34 ラジアンで、種ごとに左右を変える。

## 綿毛の描き方

冠毛の 64×5 区間と柄・種の 8 区間を、細い四角形の instance として描く。飛んだ傘には、片側を長くする係数 14% と楕円に縮める係数 10% を重ね、回転でも重なりが変わるようにする。

頭の種の向きには、元の球面の分布に緯度と角度のばらつきを加える。頭に残る毛先は半径 0.302 を中心に ±0.012 散らし、毛束の広がりにも 0.8〜1.2 倍の差を付ける。毛先の半径をほぼそろえていた作りは、外周が同じ場所で重なり、明るい弧が輪につながる原因になっていた。外側の 2 区間は約 42% の毛を弱め、残りにも毛束単位の濃淡を付けて途切れを作る。

根元で重なる毛の最初の区間は従来の 24〜46%、頭に残る柄と種は 26〜44% の不透明度にする。どちらも平均約 35% とし、規則正しく並ぶ明るい点を抑える。外周以外の毛は消さずに弱い濃淡を付け、球のふくらみを残す。乱数は再読み込みでも同じ配置になる固定のものを使う。

毛は弱い加算、柄と種は通常の透過で重ねる。線の幅を画素に合わせて補い、ぼけで幅が増えた分だけ不透明度を下げる。z=0 が頭の合焦面で、|z| が 0.30 を超えるとぼかす。手前のぼけ幅は奥の 1.75 倍にし、奥は距離に応じて不透明度を最大 48% 下げる。これは線幅による被写界深度の近似である。背景は高さ 300px の手続き的な野原を補間して拡大し、外の画像は読まない。

## 操作と寿命

マウスは押さずに動かせるので、meta の interaction は hover とする。タッチでは横からなぞる。touch-action は pan-y を基本とし、共通の touchGate を使う。縦から動かした指はスクロールに渡して息を入れず、横から始めた操作は途中で縦にも動かせる。タップ後の操作は touchGate に従って縦からも動かせる。補助の tap to drag は出さず、左下の一行に案内をまとめる。位置は左 16px・下 14px、文字は 12px・白 60%、字間 0.04em と薄い文字影にする。カメラは固定。lil-gui は最初は閉じ、風、息の強さ、奥のぼけ、逆光の 4 項目を調整できる。

寿命は 17 秒、最後の 4 秒で薄くする。CPU が状態と寿命を管理し、GPU の読み戻しを待たずに飛行中の上限を守る。頭に残る種が 18 本以下（全体の 1/4 以下）になったら 2.5 秒待ち、古い茎が 2 秒で下がって消え、新しい頭が 3.5 秒で下から現れる。消えたところで種を 72 本に戻し、流体と入力の蓄積も消す。入れ替え中は追加で放出しない。これは場面の入れ替えで、植物の実際の生長時間ではない。

動きを減らす設定では、頭と見本の 4 本を置いた一枚を描く。自動の風、放出、流体と種の更新、頭の入れ替えは進めない。操作した距離の分だけ流体と種の計算を進め、操作が止まればその姿で止まる。途中で設定を切り替えたときは現在の姿で止まる。操作を始めたら見本は頭に戻す。

共通の device、uniform、固定刻み、乱数の部品を使う。WebGPU が使えないときは一行の案内を出し、コンパイルやデバイスのエラーは画面の箱へ出す。

## 数値の検査

`node --test src/demos/nature-dandelion/*.test.mjs` で、入力・放出・軌道・頭の入れ替えを確かめる。`interaction.test.mjs` は実際の入力・候補選択・付着解除の処理を使う。高さ 400・450・500・1753px の窓で、14px おき・16ms 間隔（875px/秒）なら 6 本、その半分の速さなら 3 本、倍の速さなら 10〜11 本外れる。頭から離れた入力、静止、息の設定がゼロのとき、飛行中の上限、種を戻す瞬間に不透明度がゼロであることも検査する。

`flight.test.mjs` は実際の入力処理と、`flight-reference.mjs` の流体・並進・姿勢の数値参照実装を使う。1280×800、描画 60Hz、種の積分 120Hz、頭の中央を 380px・450ms・30 段で横になぞり、操作終了 0.3 秒・1 秒・3 秒後の全種の位置、速度、投影した画面座標を出す。息の設定 0.5・1・2 で本数と速さが増え、位置と姿勢が有限で、傘が上を向き、柄・種の端まで画面内にあることを検査する。別に未操作の見本 4 本を同じ時間だけ進め、各時点で速度が見本の最大値の 3 倍以内にあることも比べる。逆方向へ 4 倍速でなぞる最大設定と、斜め入力の速度制限も検査する。

参照実装は WGSL と同じ格子・補間・移流・圧力射影・空気抵抗・重力・姿勢の式を使うが、CPU で走る独立した実装である。GPU での実行や描画を保証する検査ではなく、見た目と実際の操作は別のブラウザで確認する。
