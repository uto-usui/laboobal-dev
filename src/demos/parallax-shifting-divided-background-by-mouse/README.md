# 分割した背景をマウスに合わせてずらす

## 何をしているか

画面いっぱいの写真を横に 5 本の帯に切り、マウスの位置に合わせて帯ごとに少しずつずらす。帯は 1 本おきに左右逆へずれ、上の帯から順に遅れて追いつく。

## 大事なところ

切って見えるのに、止まっているときは 1 枚の写真に見える。どの帯にも画面と同じ大きさの写真を丸ごと置き、帯の位置の分だけ上へずらしてから、帯の外を `overflow: hidden` で切っている。帯の中身はつながっているので、動かしたときにだけ切れ目が出る。

ずれを大きく見せているのは、偶数の帯と奇数の帯で横の向きを逆にしていること。同じ量でも、隣どうしが逆に動くと切れ目が倍に開いて見える。縦のずれ、奥行き（z）、少しの回転は全部の帯で同じ向きなので、全体としては 1 枚の写真がマウスのほうへ傾いたように見える。

もう 1 つは追いつく順番。帯ごとに 0.1 秒の短い tween を作り、上から 2 本ずつ 0.07 秒ずつ遅らせて始める。マウスを速く動かすと、上の帯が先に着き、下の帯があとから追ってくるので、写真が波のようにずれてから揃う。遅れた tween が始まるときに、同じ帯の古い tween を止める（GSAP の `overwrite: 'auto'`）ので、tween が積もって動きが濁ることがない。

量はどれも小さい。横は最大 16px、縦は 40px、回転は 2 度くらい。写真が画面からはみ出さない範囲で動かすため、写真を上下左右に 10% ずつ大きくしてある。縦の位置は、画面の上下 15% を切った範囲で 0〜100 に直しているので、画面の端までマウスを持っていかなくても動ききる。

各帯に `perspective: 500px` を付けているので、回転と奥行きの消失点は帯ごとの真ん中になる。全体に 1 つの消失点を付けたときより、帯ごとの傾きの差が少し出る。

## 作り方

GSAP の `gsap.to` に `stagger` を関数で渡し、`Math.floor(i / 2) * 0.07` で 2 本ずつの遅れにしている。横の向きは `x` を関数にして、帯の番号の偶奇で符号を変える。tween はマウスが動いたフレームだけ作る（`gsap.ticker` の中で、前のフレームから動いたかを見る）。

帯の大きさは `vw` と `vh` ではなく、外の箱の割合で決めている。写真を置く入れ物は帯の高さの 500%、上へのずれは帯の番号 × -100%。iframe の中でも外でも同じに見え、スクロールバーの分だけ横にはみ出すこともない。

## もとのデモから変えたこと

- 記事のとおり、帯をずらす中心は stagger のまま。TweenMax の `staggerTo()` を 2 回（偶数と奇数）呼んでいたのを、GSAP 3 の `gsap.to` 1 回にした。遅れ方（偶数の帯は 0、0.07、0.14 秒、奇数の帯は 0、0.07 秒）はもとと同じ
- jQuery をやめた。`$(window).width()` などは要素の `getBoundingClientRect()` に、`.positioner:even` と `:odd` は番号の偶奇にした
- tween に付けていた `perspective: '500px'` は外した。帯の CSS の `perspective` だけで奥行きが付く
- もとは写真を 110% にして `translate(-5%, -5%)` でずらしていて、下の端が少し足りなかった。上下左右に 10% ずつ大きくした
- 写真は `source.unsplash.com` のランダム画像だった（サービスが止まって何も出ていなかった）。Unsplash の猫の写真を置いた
- SCSS を普通の CSS にした。`mix(white, black, 20%)` の線の色は `#333`
- 旧デモは画像が出ないため、画面の上では動きが見えなかった。動きはコードを読み、もとのコードに写真を入れて手元で動かして比べた
