# マウスに遅れてついてくる

## 何をしているか

マウスを動かすと、大きい玉と小さい玉がマウスを追いかける。2 つとも少し遅れてついてきて、小さい玉の方がさらに遅れる。止めると 2 つとも同じ点に重なって止まる。

## 大事なところ

動きは「毎フレーム、マウスとの差の一部だけ近づく」という 1 行の式だけでできている。

```
位置 += (マウスの位置 - 位置) × 割合
```

差が大きいうちは大きく動き、近づくほど動きが小さくなる。だから急に止まらず、ふわっと減速してマウスの位置に収まる。イージングの関数を選ばなくても、自然なイーズアウトになる。マウスが動き続けている間は差がなくならないので、一定の距離を空けてついてくる。

割合が遅れ方を決める。大きい玉は 1 フレームで差の 10%、小さい玉は 5%。割合を半分にすると、追いつくまでの時間がおよそ倍になる。同じ式で割合だけ違うものを重ねると、動きに前後の順ができて、尾を引くように見える。

旧デモは、この割合を 1 フレームあたりで書いていた。そのままだと 120Hz の画面では 1 秒に 120 回近づくので、60Hz の画面の倍の速さで追いつく。作り直しでは、経過した時間から近づく量を計算する `damp` を使い、60Hz の画面で旧デモと同じ速さになるよう割合を換算している（`-60 * ln(1 - 割合)`）。

## 作り方

requestAnimationFrame のループで、毎フレーム `damp` で玉の位置をマウスへ近づけ、`transform` の `translate` に入れている。玉の真ん中がマウスに来るよう、`translate(-50%, -50%)` を続けて付けている。

マウスの位置は、デモの入れ物の左上を 0 とした座標で取る（`src/shared/pointer.ts`）。動かす前は入れ物の真ん中にしておくので、開いたときに玉が真ん中にいる。Pointer Events で取るので、スマホで指をすべらせても追いかける。`touch-action: pan-y` にしてあり、縦に指を動かしたときはページのスクロールを優先する。記事に埋め込んだとき、このデモの上を触っても記事を読み進められるようにするため。横にすべらせたときは玉が追いかける。

## もとのデモから変えたこと

- 1 フレームあたりの割合を、経過時間を使う `damp` に直した（上に書いたとおり）
- 旧デモは玉が左上から出てきた。開いたときは真ん中に置くようにした
- マウスの位置を `offsetX` で取っていたのをやめ、`clientX` から入れ物の位置を引くようにした。`offsetX` はイベントが起きた要素からの位置なので、子要素の上にマウスがあると値がずれる
- TweenLite.set を、`style.transform` に直接入れるだけにした
- 背景をサイトの暗い色にした
