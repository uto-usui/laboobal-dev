# スクロールで起き上がる

## 何をしているか

スクロールすると、横長の箱が下から上へ通り過ぎる。下にいるときは奥へ倒れていて、真ん中に来ると正面を向き、上へ行くと手前へ倒れていく。スクロールを止めても、箱は少し遅れて追いつく。

## 大事なところ

箱の形は、箱が画面のどこまで来たか（進み具合、0〜1）から決めている。進み具合の考え方は scroll-reveal と同じ。ここでは offset を -150px にして、画面に入る 150px 前から数え始めている。入ってきた瞬間には、もう倒れた姿勢で動き出している。

進み具合 p から、3 つを決める。

- 回転（X 軸のまわり）: p が 0 で 60 度、1 で -60 度。真ん中で 0 度（正面）
- 縦の位置: p が 0 で 100px 下、1 で 100px 上。スクロールより少し速く動いて見える
- 縦ののび: 真ん中で 1 倍、端に行くほど 1.1 倍。真ん中からの離れ具合 |p - 0.5| で決める

この 3 つを、スクロールにぴったり合わせるのではなく、毎フレーム差の一部（10%）だけ近づける。スクロールを止めても箱はすぐには止まらず、少し遅れて目標の姿勢に収まる。スクロールの勢いが箱に残るので、重さのある板が起き上がっているように見える。CSS の scroll-driven animations ではスクロールにぴったり合ってしまうので、この遅れは出せない。

奥行きは、箱の親に付けた `perspective` で出している。視点の位置（`perspective-origin`）は、いつも画面の真ん中に合わせ直している。視点が親の真ん中のままだと、箱がどこにあっても箱の真正面から見ることになり、上下で倒れ方の見え方が変わらない。視点を画面の真ん中に置くと、下にある箱は下から、上にある箱は上から見上げたり見下ろしたりする形になり、画面の中を通り過ぎていく感じが出る。

## 作り方

requestAnimationFrame のループで、進み具合を計算し、`damp` で回転、位置、のびを目標へ近づけ、`transform` に入れている。進み具合の計算は `src/shared/a/view-progress.ts`（scroll の 3 本で共通）。

進み具合は、動かす箱ではなく、動かさない親（`.slot`）で測る。箱は `translateY` で上下に動くので、箱で測ると、動かした分が進み具合に返ってきてしまう。

`perspective` は箱のすぐ上の親（`.slot`）に付けている。`perspective` は子にしか効かず、孫には効かない。

ライブラリ（locomotive-scroll や Lenis）は使っていない。遅れて追いつく動きはこの箱 1 つだけで、`damp` 1 行で書けるため。ページ全体のスクロールに慣性を付けるわけではない。

## もとのデモから変えたこと

- 旧デモも `perspective: 400px` を付けていたが、付けた先がスクロールする入れ物で、箱はその孫だったので効いていなかった。旧デモの箱は台形にならず、回転すると縦につぶれるだけに見えていた。作り直しでは箱のすぐ上の親に付けて、奥行きが出るようにした。旧デモが `perspective` を付けていた意図に合わせた変更で、見た目は旧デモと変わっている
- 旧デモは高さ 500px の入れ物の中をスクロールさせていた。ページそのものをスクロールさせるようにしたので、JS で `perspective-origin` を画面の真ん中に合わせ続けて、入れ物の真ん中から見ていたのと同じ見え方にしている
- 1 フレームあたりの割合を、経過時間を使う `damp` に直した
- 開いたときに箱が画面の下の方に少し見えるよう、上の余白を減らした
- 背景をサイトの暗い色にした
