# つまんで離す

## 何をしているか

画面のどこを押しても、真ん中の玉をつまんだことになる。引っぱると玉が指を追いかけ、離すと真ん中へ戻る。玉はいつも少し遅れて動く。

## 大事なところ

動きの正体は「毎フレーム、行きたい位置との差の一部だけ近づく」というだけの式。旧デモでは差の 10% だった。差が大きいうちは速く、近づくほどゆっくりになるので、勝手にイーズアウトになる。イージングの関数もタイムラインも使っていない。

行きたい位置は 2 つしかない。押している間は「押した点からどれだけ指が動いたか」、離したら 0。離した瞬間に行き先が 0 に切り替わるだけで、戻る動きのための処理はない。引っぱるときと戻るときが同じ式なので、どちらも同じ手ざわりになる。輪ゴムでつまんで離した感じが出るのはここ。

玉そのものをつかむのではなく、押した点からの移動量を使っている。だから玉の上を押す必要がなく、どこを押してもよい。玉の位置と指の位置は一致しないが、指の動いた分だけ玉が動くので、つかんでいるように感じる。

「差の 10%」は、旧デモでは 1 フレームあたりの割合だった。120Hz の画面では 1 秒に 120 回近づくので、60Hz の画面の倍の速さで追いつく。作り直しでは、1 秒あたりの近づき方に直してから使っている（`damp`）。60Hz の画面で旧デモと同じ速さになるよう、`-60 * ln(1 - 0.1)` で換算した。

## 作り方

requestAnimationFrame のループで、毎フレーム `damp` で位置を近づけ、`translate` に入れている。

GSAP の Draggable と InertiaPlugin は使っていない。Draggable は「つかんだ要素が指と一緒に動き、離した位置に残る」前提の道具で、離すと戻るこの動きとは合わない。InertiaPlugin は離したときの勢いで滑らせるためのもので、これも違う。このデモに要るのは押した点からの移動量だけなので、Pointer Events で数行で書ける。

押した点からの移動量は `src/shared/a/pull.ts` にまとめ、drag の 4 本で使い回している。`setPointerCapture` で、指が画面の外に出ても離すまで追い続ける。`touch-action: none` で、スマホで引っぱったときにページがスクロールしないようにしている。

## もとのデモから変えたこと

- ismobilejs で touch と mouse のイベントを分けていたのを、Pointer Events 1 つにまとめた
- 1 フレームあたりの割合を、1 秒あたりの近づき方に直した（上に書いたとおり）
- TweenMax.set で transform を書いていたのを、`style.translate` に直接入れるだけにした
- 背景を明るい灰色から、サイトの暗い色に変えた。玉の色は旧デモのまま
