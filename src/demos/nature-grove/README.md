# 林を植える

## 何をしているか

初夏の林の縁で、見えている地面をタップすると苗が植わり、タップした所に小さな土と芽の印がすぐ出る。苗の芽が枝と次の芽へ変わり、その先でも同じ書き換えが繰り返され、約4.2秒で若木になる。最初は3本の見本が同時に育つところから始まり、見本の途中でも植えられる。種ごとに幹の高さ・太さ・最初の分岐位置・傾き、冠の広がり、葉の量・大きさ・色が変わる。カメラは成長や木の本数によって動かさない。

主な操作は植えることだけ。横・縦のドラッグによる変形や、育て直すボタンは置かない。案内は左下の「地面をタップして木を植える」の一行。閉じたlil-guiに「芽の分岐」（2本／3本を中心に混在）と「枝の角度」を置き、設定は次に植える木へ適用する。既存の木は変えない。EnterまたはSpaceでも、見えている地面の空いた所に一本ずつ植えられる。

中央だけの範囲制限は置かず、画面の位置からカメラの光線と地面の交点を求める。手前端は画面の高さの89%まで、左右端は幅の5〜95%まで内側へ寄せた位置に根元を固定する。端以外はタップ位置のままとする。空へ向かう光線では植えない。土と芽の印は実際のタップ位置に1.2秒間出し、薄くして消す。これは表示のための単位で、生物の実際の年数や成長速度の再現ではない。

## 芽を一斉に書き換える

`tree.ts`は、枝`F`と芽`X`を区別するパラメトリックなL-systemを持つ。

```text
X(ℓ) → F(ℓ)[R₁X(s₁ℓ)]…[R_bX(s_bℓ)]
```

一回の書き換えでは、前の回の全ての芽から枝を一つずつ作り、それぞれの先に次の芽を置く。分岐の数は設定の2または3を中心にし、24%の確率でもう一方の本数を使う。最初は必ず分岐する。2世代目は27%が一芽だけを続け、3世代目以降は12%がそこで止まり、15%が一芽を続ける。残りが2本または3本に分かれる。枝ごとに方位と角度、長さをばらつかせる。芽の一覧、枝の親子関係、各回の枝数と芽数をCPUで保持する。

一回は0.7秒で、全ての芽が同時に0.52秒かけて枝になり、その先で0.18秒かけて葉が開く。これを6回繰り返す。生まれた枝と葉を一時的に明るい新緑にし、次の回には落ち着いた色へ移す。一本の木の中では世代の開始時刻をそろえ、別の時に植えた木はそれぞれの植えた時刻から育つ。

枝は生成時に三次ベジェ曲線として固定し、成長時は起点から完成形へ頂点を展開する。子の起点は親の先端と一致し、親が伸びきるまで子を出さない。最初の幹だけは長さの32%を苗として最初から見せる。既存の枝を再計算する変形、最終世代だけ枝を長くする処理、将来の枝数によって過去の枝の太さが変わる処理は使わない。世代を追加しても既存の中心線と太さは変わらない。

## 同じ種から一本ずつ違う木を作る

植えるたびに得る種から、木全体の性質と枝ごとの乱数を別々に作る。連番の種も初期状態を混ぜて相関を避ける。高さの基準は0.7〜1.3倍、太さは0.75〜1.3倍、最初の分岐までの長さは高さとは別に0.68〜1.48倍にする。分岐角の基準は0.65〜1.5倍、枝の縮み方は木ごとに0.7〜0.85倍、さらに枝ごとに0.8〜1.16倍にする。これにより、長い一本幹、低い分岐、細長い冠、広い冠が混ざる。

根元からの傾きと片側への伸びやすさを種から決める。高さと横位置から格子ノイズを滑らかに補間し、枝の向きとベジェ曲線の制御点を曲げる。毎フレーム揺らすのではなく、植えた時点で中心線を固定する。上向きの補正と、空いた側への補正を加える。広い分岐角が重なっても、枝が下へ伸びて地面へ潜らないよう上向きの成分を少し残す。芽が止まる位置も違うため、左右対称のY字が繰り返されにくい。

地面は平面のままとする。高低差を付けると、既存のタップ位置の判定と根元の接地も変える必要があるため、今回は近隣の木との距離を育ち方へ反映する。

## 完成した冠まで画面に収める

木を生成した時点で、完成した枝・個別の葉・遠景用の面の全頂点をカメラに照合する。上と下に画面の5%、左右に2%の余白を残せる倍率を求め、1倍を上限として木全体を根元から同じ比率で縮める。高さだけを押し縮めず、幹の傾き、冠の縦横比、枝分かれ、葉色はそのまま残す。成長中や別の木を追加したときに倍率を変えない。画面の大きさが変わったときは照合し直す。横長画面の端に植えた根元が縦長画面から外れる場合に限り、リサイズ時にカメラを下げて根元も収める。

成長の起点と完成形の両方に同じ倍率を掛け、影にも同じ頂点関数を使う。葉の投影幅にも倍率を反映し、縮めた木で個別の葉が粒状に残ることを避ける。

## 先の木の陰を避ける

新しく植えるとき、3m以内に先に植えた木があれば、近いものほど強く、その根元から離れる方向を足し合わせる。その方向へ各世代の枝を少し向ける。向きの補正は上限を設け、木全体が横倒しになるのを避ける。既存の木を押したり、その形を変えたりしない。

実際の光量や樹冠同士の遮蔽を計算する光合成のモデルではなく、光のある空間へ伸びる向きを、近隣の配置から近似する。同じ位置に重ねて植えた場合は離れる方向を定められないため、その一本との関係では補正しない。

## 葉と林の見せ方

手前は、葉柄から始まる細長い曲面の葉を枝先に2〜6枚付ける。木ごとの茂り具合と枝ごとの乱数で枚数を変え、葉の大きさは0.78〜1.26倍にする。中央の葉脈、表裏の明るさ、逆光の透けを材質で表す。緑を基調に、木ごとのRGBの比率で黄み・青み・濃さを変え、枝と葉ごとの微差も頂点に保存する。新しい葉は明るい黄緑、古い葉は落ち着いた緑へ移り、日向と陰でも色の比率を少し変える。遠くでは、同じ枝先の葉を、縁に8枚分の葉先を残した一続きの面へ統合する。葉の集まりの内側に穴や点のマスクを置かない。

木ごとの大きさを掛けた葉幅（基準0.17m）をカメラへ投影し、幅が9 CSS px未満になれば面を使う。3px未満になるまで個々の葉を残さず、遠景では早めにまとめる。遠景の面にも同じ木の茂り具合・大きさ・色を使う。個別の葉と面は同時に描かず、深度パスにも同じ切り替えを使う。リサイズで判定が変わっても枝の中心線は変わらない。縮小時の粒や砂のような見え方を避けるための初期値で、最終的な見え方はブラウザで評価する。

明るい空と、色が大きくうねる草地を置く。奥の林縁は、幹と葉形の輪郭を持つ大きな面でまとめた、動かない遠景とする。葉や土へ細かな粒のノイズを足さず、幹と主枝の間の空間を残す。

## 本数と描画の負荷

育てる木は最大12本。13本目を植えると最古の木を0.7秒で薄くし、GPUの資源も解放する。消えかけの木は最大1本だけ保持するので、描画上の一時的な上限は13本。連打された場合は、先に消えかけていた木を片付けてから次の一本を薄くする。退場中の木は影を落とさない。

木を植えたときだけCPUで枝と葉のメッシュを作る。管は長さ方向8区間、円周8点。成長中は木ごとの32byteのuniformだけを書き換え、頂点の展開はWebGPUで行う。完成した木のメッシュは更新しない。最大毎秒30回、4倍MSAA、最大240万画素で描き、成長も退場も終わったらループを止める。影は1024×1024の深度シャドウマップで、形や葉の距離判定が変わったときだけ描き直す。

共通uniformの`TreeScene`は208byte。group 0はbinding 0が共通uniform、1が深度画像、2が比較サンプラー。`TreeObject`は32byteで、group 1のbinding 0に成長時間、不透明度、倍率込みの葉の大きさ、詰め物を各4byte、その後に根元の座標12byteと木全体の倍率4byteを置く。深度パスのgroup 0は共通uniformだけ。項目の並びとWGSLの構造体は同じ定義から作る。頂点は位置3、法線3、UV・誕生時刻・材質4、成長の起点3、葉色3の16個のfloat、64byte。深度パスと色のパスは同じ成長関数を使う。

## 入力と動きを減らす設定

`touch-action: pan-y`で記事の縦スクロールを残す。7px以上動いた操作、pointercancel、要素の外へ出た操作では植えない。指を動かした量で木を変える操作やポインターの捕捉は使わない。見える案内は一行だけとし、土と芽の印は入力を遮らない。EnterまたはSpaceでは根元の投影位置に同じ印を出す。植えた本数の通知はスクリーンリーダーへ渡す。

動きを減らす設定では、最初の見本は完成した姿を見せる。読む人がタップやキーで始めた4.2秒の成長は残す。途中で設定を変えても、始まった一回の成長は最後まで進む。非表示のタブや画面外では時間を止める。WebGPUが使えない場合やdeviceを失った場合は案内へ替え、ページを離れると入力、GUI、ループ、GPUの資源を片付ける。

## 確認を分担するところ

Nodeの検査は次で繰り返せる。

```sh
node src/demos/nature-grove/check-variation.mjs
```

同じ設定・周囲の木なしで種1〜10を比べ、高さ、冠の最大水平幅／高さ、実際の枝先の数、根元から冠の頂点平均までの水平距離、成熟葉の基準色に頂点色を掛けた平均RGBをJSON行で出す。これは質量ではなく冠の面の頂点平均による偏りの指標で、葉色は照明・影・表示色への変換前の値とする。高さは範囲0.7m超、冠の比率と偏りは範囲0.2超、RGBはそれぞれ範囲0.02／0.06／0.015超を下限とし、丸めた値の重複も検査する。さらに近隣の木を順に加える10本の林も測り、周囲の配置が枝へ反映されることを確認する。画面上で十分違って見えるかは別途作者が確認する。

書き換え回数と枝数・芽数、既存の中心線の不変性、親子の接続、時間割、葉の投影幅、カメラと地面の交点、配列と頂点の有限性を確かめる。ブラウザでの絵と操作は別途確認する。960×450、360×450、480×300で、0.7秒、1.4秒、2.8秒、4.2秒の枝分かれと葉の開き、連続して植えたときの位置、本数上限、縦スクロールを確認する。
