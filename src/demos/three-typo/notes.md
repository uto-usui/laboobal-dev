# 溶ける文字

## 何をしているか

黒い画面に赤い大きな文字を 3 つ並べ、その一部だけを溶けたように横へ流す。崩れる場所はゆっくり移り、文字はいつも読める形を保っている。

## 大事なところ

崩れる場所をしぼっているのが肝。ノイズの値（-1〜1）を 8 乗すると、ほとんどの場所は 0 に近くなり、ノイズの山のところだけが大きく残る。その値だけ文字の uv をずらすので、文字の大部分は動かず、ところどころがぐにゃりと流れる。全体を少しずつ歪めるより、一部が大きく崩れるほうが「溶けている」と感じる。

ノイズは domain warping（ノイズの値でノイズの座標をずらす）にしている。ふつうのノイズよりうねった形になり、崩れた部分が垂れたり渦を巻いたりして見える。座標の片方に時間を足してあるので、崩れる場所がゆっくり流れていく。

ノイズの座標は横 2.2、縦 8.8 倍。縦に細かく横に長い模様になるので、崩れ方も横へ流れる筋になる。文字の縦の線が横へちぎれて見えるのはこのため。

文字の間を広くあけて、崩れるところが 1 文字ずつ見えるようにしている。

## 作り方

文字は 2D の canvas に書き、`CanvasTexture` にして three に渡す。フォント（Montserrat）を読み終えてから書く。iframe の大きさが変わったら書き直す。

three の `ShaderMaterial` で画面いっぱいの板を 1 枚描き、フラグメントシェーダーでノイズを作って、ずらした位置の文字の色を読む。ノイズは共有の `simplex-noise.glsl` の `snoise(vec2)`。模様の大きさは画面の長いほうの辺に合わせているので、iframe の縦横比が変わっても崩れ方が同じに見える。

## もとのデモから変えたこと

- 旧デモの文字は「C N J」。意味の分からない字だったので「L A B」にした
- 旧デモは `pow(n * 0.8, 8.0)` で、n が負のときの答えが決まっていなかった（GLSL の `pow` は負の数を受けない）。`abs` を付けた。8 乗なので、正しく計算すれば同じ値になる
- 旧デモは正方形の板を画面より大きく置き、その一部を見せていた。画面いっぱいの板にし、ノイズの座標の取り方で同じ大きさの模様にした
- 旧デモの、文字のない場所にざらつきを足す行は、背景が透明で何も変わらなかったので外した。没になったもう 1 つのシェーダー（`TypoFontTexture2.fs`）は使っていない
- 出どころは分からない。domain warping はよく使われる形
