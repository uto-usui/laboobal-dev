# スクロールの視差いろいろ

## 何をしているか

縦に長いページを、なめらかに減速するスクロールで動かし、写真や文字をそれぞれ違う速さでずらす。写真の枠と中の写真が逆向きに動く、枠がスクロールに遅れて追いつく、タイルの列が横へ流れる、写真が画面に貼り付いて枠だけが通り過ぎる、文字が回る、最後の一行が 1 文字ずつ波打って追いついてくる。ページの背景の色は、スクロールの進み具合で少しずつ色相が変わる。

## 大事なところ

視差は「要素が画面の中心からどれだけ離れているか × 速さ」だけ要素をずらすことで作っている。速さが正なら、スクロールより速く上へ動いて手前にあるように見え、負なら遅く動いて奥にあるように見える。枠（正）と中の写真（負）を逆にすると、枠が窓になって、写真が奥でゆっくり動いて見える。中の写真は上下に 20% ずつ大きくしておき、ずれても枠の中に隙間が見えないようにしている。

いちばん気持ちいいのは、遅れて追いつく動き（locomotive-scroll 4 の `data-scroll-delay`）。要素の目標の位置は上と同じ式で決めるが、要素はそこへ毎フレーム差の一部（60fps で 5%）だけ近づく。スクロールを止めても少しのあいだ動き続けて、すっと止まる。重さがあるように見える。最後の「Back To Page Top」は 1 文字ずつ近づく割合を変えていて（先頭 18% から 1 文字ごとに 1% ずつ減らす）、先頭の文字ほど早く追いつく。そのため文字の並びが波のようにしなって、左から順に揃う。

スクロール自体も、ホイールの量をそのまま使わず、Lenis がなめらかに減速させている。スクロールの減速と、要素ごとの遅れが重なるので、ページ全体がゆったり動く。

タイルの列の横の流れは、ページは縦にスクロールしているのに、列だけ横へずらしている。偶数と奇数の列で向きを逆にすると、すれ違って見える。列ごとに速さを変えると（1 と 3）、奥行きが出る。ずらす量は、タイルのブロック全体の進み具合（ブロックが画面の下から入って上へ抜けるまでを 0〜1）から決めていて、列ごとに別々には測らない。ブロックが画面の真ん中にあるときにずれが 0 になる。

写真が画面に貼り付く部分は、枠を切り抜きにし、中の写真を画面の上に固定したままにする。枠だけが動くので、窓の向こうに写真が止まっているように見える。

## 作り方

locomotive-scroll 5.0.1 を使っている。5 は中で Lenis 1.3 を動かし、ページのスクロールはブラウザのふつうのスクロールのまま（4 のようにページ全体を transform で動かさない）。旧デモが使っていた属性が 5 にあるかを、`node_modules/locomotive-scroll` の中で確かめた。

| 旧デモの属性（4）                              | 5 にあるか                                           | 作り直しでどうしたか                                                                 |
| ---------------------------------------------- | ---------------------------------------------------- | ------------------------------------------------------------------------------------ |
| `data-scroll-speed`                            | ある（意味が変わった）                               | そのまま使う。値は下のとおり換算した                                                 |
| `data-scroll-direction="horizontal"`           | ない（向きはページ全体でしか決められない）           | `data-scroll-css-progress` で入る `--progress` から、CSS の `translate` で横にずらす |
| `data-scroll-target`                           | ない                                                 | ブロックに `data-scroll-css-progress` を付け、中の列は継承した `--progress` を使う   |
| `data-scroll-delay`                            | ない                                                 | `main.ts` で自前に書いた（下）                                                       |
| `data-scroll-sticky`                           | ない                                                 | CSS の `position: sticky`。5 はふつうのスクロールなので、そのまま効く                |
| `data-scroll-call`（背景の色）                 | ある（`window` に CustomEvent を投げる形に変わった） | 使わない。スクロールの進み具合を CSS 変数にして、ページと枠の背景で使う              |
| `data-scroll-id` と `currentElements`（回転）  | ない                                                 | `data-scroll-css-progress` と CSS の `rotate`                                        |
| `data-scroll-offset`、`is-inview`              | ある                                                 | そのまま使う（見出しと文の現れ方）                                                   |
| `data-scroll-section`、`data-scroll-container` | ない（要らなくなった）                               | 外した                                                                               |

`data-scroll-speed` の意味は 4 と 5 で違う。4 は「画面の中心からの距離 × 値 / 10」ずらした。5 は、要素が画面の下から入って上へ抜けるまでの進み具合を -1〜1 にし、それに画面の高さと値を掛けてずらす。同じ動きにするには、5 の値 ≒ 4 の値 / 10 ×（画面の高さ + 要素の高さ）/（画面の高さ × 2）。最初の画面にある要素（題名）は 5 では 0 から動き出すので、別の式で換算した。どれも、旧デモと並べてスクショで見ながら合わせた。

遅れて追いつく動きは 5 にないので、自前で書いた。`data-lag` を付けた要素ごとに、目標の位置を 4 と同じ式（画面の中心から要素の中心までの距離 × 速さ / 10）で決め、共有の `damp` で近づける。`damp` の速さは、4 の delay の値（60fps で 1 フレームに近づく割合）から `-60 × log(1 - delay)` で決めた。フレームレートが違っても同じ遅れ方になる。要素の位置は、ページの大きさが変わったとき（`onResize`）に測り直す。

ページの根元は `overflow: clip` にしている。回したタイルや長い一行が横にはみ出すのと、視差でずらした要素が下にはみ出すと、ページが伸びてスクロールの終わりが動き、背景の色が揺れ続けたため。`hidden` にするとそこがスクロールの入れ物になり、`position: sticky` が効かなくなる。

`prefers-reduced-motion` が有効なときは、ホイールのなめらかな減速と、遅れて追いつく動きを止める（位置は目標にすぐ合わせる）。locomotive-scroll 5 はタッチの端末では視差を止める。CSS の `--progress` で動かしているもの（横の流れ、回転）は、タッチでも動く。

## もとのデモから変えたこと

- locomotive-scroll 4 から 5 にした。属性の扱いは上の表のとおり
- 説明の文を、5 で使っているもの（`data-scroll-speed`、横の流れ、`data-scroll-css-progress`、`position: sticky`）に書き換えた。旧デモの文は、5 にない属性の説明だった
- 背景の色は、旧デモではページと「画面に入っている枠」だけを毎フレーム塗っていた。作り直しでは CSS 変数 1 つにして、全部の枠がそれを使う。画面の外の枠の色は見えないので、見え方は同じ
- 中の写真を枠より上下に大きくした。旧デモは中の写真が枠と同じ大きさで、ずれた分だけ枠の端に隙間ができる作りだった
- 最後の「Back To Page Top」をボタンにし、押すとページの先頭へなめらかに戻る
- 画像は、旧デモの写真の出どころが確かめられていないので使っていない。このデモのために花とボケの模様を canvas で描き、JPEG に書き出したものに差し替えた。旧デモの写真と同じく、白黒に近づけて背景の色と掛け合わせている
