# 引っぱる向きにのびる線

## 何をしているか

画面に 80 個の点が散らばっている。どこかを押して引っぱると、点が引っぱった向きの線にのび、赤くなる。真ん中の大きな玉は、引っぱるほど小さくなって、引っぱった向きへ遠ざかる。離すとすべて元に戻る。

## 大事なところ

80 個とも同じ式（押した点からの移動量へ、毎フレーム差の一部だけ近づく）で動いている。ばらばらに見えるのは、点ごとに引っぱりへの倍率を 0.25〜2 のあいだでランダムに変えているから。倍率が大きい点ほど遠くへ行き、長くのび、早く赤くなる。同じ操作から、奥行きのあるような、風が吹いたような動きが出る。

線の向きは、点が今いる位置（引っぱりの量）の角度から決めている。`atan2(y, x)` で角度を出し、縦の線を 90 度倒してその向きに合わせる。のびる長さは移動量の大きさに比べる。点は動いている向きに長くなるので、動きのぶれ（モーションブラー）のように見える。

真ん中の玉は逆の役を持つ。引っぱるほど小さくなり、移動量の 2 倍の距離を動く。線が手前に流れてくるのに対し、玉は奥へ逃げていくように見える。

近づく割合は、線が 1 フレームで差の 7.5%、玉が 10%。線を少し遅らせて、玉が先に動き、線があとから流れてくる順にしている。

## 作り方

drag の 4 本と同じく、requestAnimationFrame と `damp`、`src/shared/a/pull.ts` で書いている。

線は 1px 四方の `<i>` を 80 個置き、`transform` の `scaleY` でのばしている。幅と高さを変えるのではなく `transform` だけを変えるので、80 個でも毎フレームのレイアウトの計算が起きない。

点の置き場所は、画面の外に少しはみ出す範囲（-5%〜105%）にしている。端で線が途切れて見えないようにするため。割合で置いているので、iframe の大きさが変わっても散らばり方が保たれる。

色は CSS の `color-mix(in oklab, …)` で混ぜ、JS は `--t` に 0〜1 を入れるだけ。

## もとのデモから変えたこと

- 点の置き場所を px から % にした。旧デモは読み込んだときの大きさで決めていた
- chroma-js をやめ、CSS の `color-mix()` にした
- 1 フレームあたりの割合を、1 秒あたりの近づき方に直した
- 背景をサイトの暗い色にした
