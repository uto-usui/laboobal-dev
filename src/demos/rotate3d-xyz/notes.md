# 3 つの軸で回る点

## 何をしているか

12 個の丸を空間に散らし、X、Y、Z の 3 つの軸のまわりに回し続ける。マウスの位置で、X 軸と Y 軸のまわりの回る速さと向きが変わる。

## 大事なところ

回しているのは丸ではなく、丸の座標。毎フレーム、各点の x、y、z を回転の式で少しだけ回し、`translate3d` でその位置に置く。丸そのものは傾けないので、いつも正面を向いた円のまま、手前に来ると大きく、奥へ行くと小さくなる。入れ物ごと CSS の `rotate` で回すと、丸が横から見た紙のように細くつぶれてしまう。

点ごとに回る速さを変えている（1 秒に 60〜240 度）。全部を同じ角度で回すと 1 つの塊が回っているだけに見えるが、速さが違うので点どうしの並びが崩れ、すれ違い続ける。

マウスの位置は「どこを向くか」ではなく「どれだけの速さで、どちら向きに回るか」に使っている。真ん中では X 軸と Y 軸の回転が止まって Z 軸だけが回り、端へ寄るほど速く回り、反対側へ行くと逆に回る。上下の動きが X 軸、左右の動きが Y 軸に効く。速さはマウスにすぐ合わせず、毎フレーム差の一部だけ近づけるので、向きを変えるときにいったん緩んでから逆に回り出す。

色は淡い水色、赤、濃い緑の 3 つで、`mix-blend-mode: multiply` で重ねている。重なったところが暗くなるので、丸どうしが前後に重なったことが分かる。multiply は重ねる順番で結果が変わらないので、手前と奥の描く順番を気にしなくてよい。奥行きは大きさだけで読ませている。

## 作り方

GSAP は使わず、`loop` で毎フレーム座標を回して `transform` を書いている。回転は 2 次元の回転の式を、軸ごとに残りの 2 つの座標へ当てたもの（X 軸なら y と z、Y 軸なら x と z、Z 軸なら x と y）。

座標は画面の大きさ（unit）に対する割合で持ち、描くときに unit を掛ける。unit は高さと、幅を 1.48 で割ったものの小さいほう。丸の大きさ（unit の 10%）と perspective（unit の 1.6 倍）も unit から決めるので、iframe の大きさが変わっても並びと奥行きの見え方が変わらない。

マウスへの追いつき方は `damp` で、1 秒あたりの強さ 6。旧デモの「1 フレームに差の 1 割」とほぼ同じ。

## もとのデモから変えたこと

- 旧デモは `gsap.set` で毎フレーム値を入れていた。`style` に直接書くだけにした
- 旧デモはマウスの縦の位置を幅で、横の位置を高さで割っていて、範囲がずれていた（高さ 500px、幅 740px のとき、下の端まで動かしても反対向きの速さが最大の 3 分の 1 ほどにしかならず、横は右の 3 分の 1 がどこでも最大になる）。縦は高さ、横は幅で割るように直した。上下で X 軸、左右で Y 軸という組み合わせはそのまま
- 始まりは旧デモと同じく、マウスが左上にあるときの回り方にしている。マウスを動かす前から 3 つの軸で回る
- 速さを 1 フレームあたりから 1 秒あたりに直した
- 座標、丸の大きさ、perspective を画面の大きさの割合にした。旧デモは高さ 500px の決め打ち
- タッチでも回せるよう、`pointermove` で拾う
