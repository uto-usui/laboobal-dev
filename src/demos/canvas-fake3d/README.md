# 深度の画像で立体に見せる

## 何をしているか

1 枚の絵と、それと組になった白黒の深度の画像（白いほど手前）を使い、マウスの位置に合わせて絵の画素を深度の分だけずらす。平らな絵なのに、のぞき込む向きが変わったように見える。

## 大事なところ

ずらす量は「深度 − 0.5」に比例させる。深度 0.5 の面は動かず、それより手前はマウスの側へ、奥は反対へずれる。手前と奥が逆に動くので、その間に回り込んだような奥行きが生まれる。全体を同じ向きに動かすだけでは、絵が横に滑るだけで立体には見えない。

深度の画像はぼかしておく。段差のある深度のままずらすと、手前のものの輪郭で画素が引きちぎれたように裂ける。ぼかすと段差がなだらかな坂になり、輪郭のまわりが少し伸びるだけで済む。本物の写真の深度の画像（rose-map のような）も、輪郭がぼけたものを使う。

ずらす量は小さく保つ。大きくするほど立体感は増えるが、輪郭の伸びが見えて嘘がばれる。横は縦より大きくしている（`uThreshold` が横 22、縦 34）。人は横にのぞき込むことのほうが多く、縦に大きく動くと不自然に見える。

マウスには遅れて追いつかせる（旧デモは毎フレーム差の 5%）。すぐに追うと絵がマウスに貼りついたように見え、ゆっくり追うと重さのある物をのぞき込んでいる感じが出る。

画面の端でずれた先が絵の外に出たら、端で折り返して読む（`mirrored`）。端の色を引き伸ばすより目立たない。

## 作り方

three の `ShaderMaterial` で、画面いっぱいの板を 1 枚描く。絵と深度の画像を 2 つのテクスチャとして渡し、フラグメントシェーダーで深度を読んでから、ずらした位置の絵の色を読む。

絵は写真ではなく、`scene.ts` で球を 34 個重ねて canvas に描いている。1 画素ずつ、いちばん手前の球の表面の高さを求め、絵には陰影を、深度の画像にはその高さを書く。同じ計算から両方を作るので、絵と深度がぴったり重なる。深度のぼかしは、横と縦に分けて平均をとる計算を 2 回かけて自分で出している。canvas の `ctx.filter` の blur はブラウザの対応にばらつきがあり、効かないときは黙って無視されて、段差のままの深度になってしまうため。背景のぼけた葉や影も、blur ではなく縁が透明になる放射グラデーションで描いている。写真を使うときは、写真と深度の画像の組を用意して差し替えればよい。

絵は画面いっぱいに切り取って貼る（CSS の `object-fit: cover` と同じ）。左上に深度の画像を小さく出している。

タッチの端末ではマウスが来ないので、ゆっくり 8 の字を描くように自動で動かす。

## もとのデモから変えたこと

- 旧デモは WebGL を直に書いていた。three の最新版で、板 1 枚とシェーダーに書き直した
- 写真（rose.jpg）と深度の画像（rose-map.jpg）は出どころを確かめている途中なので使わず、canvas で描いた絵と深度に替えた
- 旧デモはマウスの量を 0.1 倍に弱めていて、動きがほとんど見えなかった。もとの akella/fake3d（1 倍）と旧デモの間くらいにした
- 旧デモはページ全体のマウスの位置を見ていた。iframe の中で動くよう、デモの箱の中の位置を見る
