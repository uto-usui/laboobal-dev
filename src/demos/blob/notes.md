# 波打つ球

## 何をしているか

薄紫の球がゆっくり回りながら、表面を波打たせて形を変え続ける。マウスを動かすと、球がマウスの方へ遅れてついてきて、マウスの横の位置に合わせてカメラが球のまわりを回り込む。マウスが画面の下にあるほど、球は大きく波打つ。

## 大事なところ

形が変わるのは、球の頂点ごとに、中心からの距離（半径）を 3D のノイズで伸び縮みさせているから。ノイズには頂点のもとの位置を入れるので、隣り合う頂点はほぼ同じだけ伸び、表面がなめらかにうねる。位置に掛ける数（0.006）が小さいほど、うねりは大きくゆるやかになる。時間は x と y に別々の速さ（0.0002 と 0.0003）で足していて、うねりが同じ向きに流れ続けない。

伸び縮みの幅は `ノイズ × 0.2 × (マウスの縦の位置 + 0.1)`。マウスが上にあると 0.02 くらいでほぼ球のまま、下にあると 0.22 くらいで大きく歪む。マウスの位置は 0.3 秒かけて追いかけるので、急に形が変わらない。

球の位置は、マウスの位置へ 2 秒かけて減速しながら近づく（`power3.out`）。マウスを止めてもしばらく動き続け、重さのある物がふわっと寄ってくるように見える。縦は画面の座標と three の座標の向きが逆なので、マウスを下へ動かすと球は上へ動く。旧デモからそうなっていて、作り直しでも変えていない。

カメラは、マウスの横の位置を 0〜360 度にした角度へ、とてもゆっくり（毎秒、差の 3 割くらい）近づく。マウスを大きく動かすと、少し遅れて視点が回り込み、光の当たり方が変わる。

## 作り方

three.js で、20 面体を 4 回細かくした球（`IcosahedronGeometry(100, 4)`）を、毎フレーム頂点を動かして描いている。頂点を動かしたら `computeVertexNormals()` で法線を計算し直す。

`IcosahedronGeometry` は面ごとに頂点が分かれているので、そのまま法線を計算すると面ごとに陰影が付き、角張って見える。`BufferGeometryUtils.mergeVertices` で同じ位置の頂点を 1 つにまとめてから使う。まとめる前に法線と UV を消しておかないと、継ぎ目の頂点がまとまらない。

ノイズは共有の `createNoise` の `noise3D`。マウスへの追いかけは GSAP、カメラの回り込みは共有の `damp` で、どちらもフレームレートに左右されない。

光は、上から白、下から青の `HemisphereLight` を 2 つと、紫の `DirectionalLight`。材質は `MeshPhongMaterial` で、少しだけ青緑に自ら光らせている。

## もとのデモから変えたこと

- 旧デモは three r121 の `Geometry` の `vertices` を書き換えていた。今の three にはないので、`BufferGeometry` の位置の配列を書き換える形にした
- 今の three は色を線形の空間で計算し、最後に sRGB に直して出す。旧デモの光の色（紺の `0x0c056d`、紫の `0x590d82`）と明るさのままだと、青みが消えて灰色の球になった。旧デモと並べて見ながら、下からの光を明るい青（`0x2a2ad0`）、平行光を明るい紫（`0x8a4dff`）にし、明るさと自ら光る強さを決め直した
- 旧デモは 2 フレームに 1 回だけ描いていた。毎フレーム描き、回転とカメラの追いかけを秒あたりの量にした。速さは旧デモに合わせた
- マウスの横の位置で決める形の歪み（`force.x`）は、旧デモでも使われていなかったので外した
- マウスは `mousemove` から `pointermove` にして、タッチでも動くようにした
- 描画の解像度を devicePixelRatio に合わせた（旧デモは 1 で固定）。2 で止める
- 画面の大きさは window の resize ではなく、canvas の ResizeObserver で見る
