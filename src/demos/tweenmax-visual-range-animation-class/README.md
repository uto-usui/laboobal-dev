# 見えている間だけスクロールに合わせて動かす

## 何をしているか

縦に並んだ箱が、画面に入るとふわっと出て、出ているあいだは中の写真がスクロールに合わせて少しずつ上へずれる。画面から出ると消える。

## 大事なところ

見えているかどうかの判定に、画面の端から 100px の余白を取っている。箱の上端が画面の下から 100px 入ったところで出し、箱の下端が画面の上から 100px のところまで来たら消す。端ぎりぎりではなく少し内側で切り替えるので、出るところと消えるところがちゃんと見える。出し入れは CSS の `opacity` の 0.5 秒の transition。

中の写真の動きは、箱の中身を箱より大きくしておくことで作っている。箱は 300px、写真は 400px で、はみ出した 100px ほどを、見え始めから見え終わりまでのあいだに動かす。箱は普通にスクロールし、中だけが少し速く上へ抜けるので、窓の向こうの写真がずれていくように見える。

スクロールにぴったり合わせず、0.5 秒遅れて追いつかせている。ホイールを 1 段回すと 100px 前後とぶが、写真はそのあいだを滑らかにつなぐ。この遅れがなくなると、写真がスクロールと一緒にかくかく動く。

## 作り方

GSAP の ScrollTrigger を使った。箱ごとに 1 つ作り、`start: 'top bottom-=100'` と `end: 'bottom top+=100'` で見えている範囲を決め、`toggleClass` で出し入れのクラスを付け外しし、`scrub: 0.5` で写真の `y` を 0.5 秒遅れて追わせている。

CSS の scroll-driven animations でも、スクロールの量に合わせて動かすことはできる。ただし、スクロールにぴったり付いて動くので、0.5 秒遅れて追いつく柔らかさが出ない。もとの動きを同じ質で出せないので、GSAP にした（docs/history/rebuild-plan.md の 3 章）。スクロールそのものはページの普通のスクロールで、慣性は付けていない。

## もとのデモから変えたこと

記事の本文には、TweenMax と自前のクラス `scrollPosition` のコードが載っている。違いは次のとおり。

- `scrollPosition` クラスの仕事（`scroll` イベントで位置を見て、範囲に入ったら `is-show` を付け、範囲の中でコールバックを呼ぶ）を、ScrollTrigger の `start`、`end`、`toggleClass` に任せた。`offset = 100` は `bottom-=100` と `top+=100` にあたる
- `TweenMax.to(target, .5, { y })` をスクロールのたびに作っていたのを、`scrub: 0.5` にした。どちらも 0.5 秒遅れて追いつく
- 写真を動かす量は、記事では `value / windowH * 100`（画面の高さあたり 100px）。ここでは、見えている範囲を動ききるあいだに、はみ出した分（110px）を動かす。速さはほぼ同じで、端で写真の外が見えることがない
- 記事のクラスは、箱の位置と画面の高さを読み込んだときに 1 回しか測らないので、画面の大きさが変わるとずれた。ScrollTrigger は大きさが変わると測り直す
- 写真は `source.unsplash.com` のランダム画像（同じ URL なので 7 個とも同じ写真）だった。Unsplash の写真 3 枚を順に並べた
- 背景の写真を `<img>` と `object-fit: cover` にした
- もとは箱が左に寄っていた（`text-align: center` が箱に効いていなかった）。真ん中に並べた
- SCSS を普通の CSS にした。`rgba(black, .5)` は `rgb(0 0 0 / 50%)`
