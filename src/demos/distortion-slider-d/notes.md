# ゆがんで切り替わる（縦）

## 何をしているか

写真のスライダー。次の写真に切り替わるとき、写真が縦方向に溶けて垂れ落ち、垂れた筋の中から次の写真が現れる。

## 大事なところ

仕組みは distortion-slider-a と同じで、写真の各点を模様の明るさの分だけずらして読み、1 枚目は進むほど崩し、2 枚目は進むほど戻し、2 枚を重ねている。

このデモは y だけをずらし、x はそのまま。distortion-slider-c の縦向き版で、同じ列の点は同じ列から読むので、写真が縦の筋になって垂れる。

強さは a と同じ 10 で、とても大きい。少しずらしただけで写真の上下の外を読むことになり、写真の上端と下端の色が縦に引きのばされる。そのため、切り替えの途中は、写真の上端と下端の色をした縦じまが、模様の形に沿って流れ落ちるように見える。

## 作り方

three の `ShaderMaterial` で、画面いっぱいの板を 1 枚だけ描いている。カメラは使わず、頂点シェーダーで -1〜1 の板をそのまま画面に置く。切り替えの進み具合 `uProgress` を GSAP で 0 から 1 へ 2.5 秒（`expo.inOut`）で動かし、動いている間だけ描き直す。止まっている間は描かない。

切り替え終わったら、見た目は 2 枚目のまま、2 枚目を 1 枚目の枠に移して `uProgress` を 0 に戻す。こうすると、シェーダーはいつも「1 枚目から 2 枚目へ」だけを書けばよい。

右の番号は、今の番号の線を右へ縮めてから、1 秒あとに次の番号の線を左からのばす。線の縮む向きと伸びる向きを `transform-origin` の左右で切り替えているので、線が右へ流れていくように見える。

3 秒ごとに自動で次へ進む。クリック（タップ）とホイールでも進む。切り替えている間は次を受け付けない。`prefers-reduced-motion` のときは自動では進まない。

スライダーの本体は `src/shared/a/distortion-slider.ts` にあり、4 本で共通。デモごとに違うのは、フラグメントシェーダーの「どこをどれだけずらすか」の数行と、ゆがみの強さだけ。

### ゆがませる模様

旧デモは、ゆがませる模様をグレースケールの画像で持っていた。この画像は出どころを確かめているところなので使わず、模様をシェーダーの中でノイズから計算している（`src/shared/a/glsl/distortion.glsl`）。simplex noise を 5 段重ね（fbm）、`smoothstep` で明暗を強めている。

- `grain`: 座標を 45 度近く回し、片方向に縮めてからノイズを取る。斜めに流れる筋の入った、明暗の強い模様になる。旧の 01.png に寄せた
- `cloud`: 回さず縮めず、むらのある雲のような模様。旧の 03.jpg に寄せた

画像を読む代わりに毎回計算しているが、描くのは切り替えている間だけなので重くならない。

## もとのデモから変えたこと

- three r120 の `PlaneBufferGeometry` と `OrthographicCamera` を、今の書き方（`PlaneGeometry` 1 枚とカメラなしの頂点シェーダー）にした
- 旧デモは写真を板の大きさに引きのばしていて、縦横比が崩れていた（ライオンがつぶれて見えていた）。CSS の `object-fit: cover` と同じになるよう、シェーダーで座標を直している（`cover`）
- ゆがませる模様を、画像からシェーダーの中の計算に変えた（上に書いたとおり）
- 写真は Unsplash から落としてリポジトリに置いた。旧デモは毎回 `images.unsplash.com` から読んでいた
- 旧デモは、自動で進むほかはホイールでしか進められなかった。クリック（タップ）でも進むようにした。記事に埋め込んだとき、ホイールはページのスクロールの途中で触れてしまうことが多いため
- 右の番号に `mix-blend-mode: difference` を付けた。旧デモは白い字のままで、明るい写真の上では見えなかった
- TweenMax と TimelineMax を `gsap.to` と `gsap.timeline` にした
