# draw 関数で円を描き続ける

## 何をしているか

灰色の横長の帯に、白い小さな円を 1 つずつ、でたらめな位置に描き足していく。前の円は消さないので、しばらくすると帯は重なった円で埋まる。processing.js の入門の記事の 1 本で、`setup()` と `draw()` の分け方を見せる。

## 大事なところ

Processing のスケッチは、2 つの関数に分けて書く。

- `setup()`: 最初に 1 回だけ。ここでは画面の大きさを決めるだけ
- `draw()`: そのあと 1 秒に 60 回くり返す。ここでは、でたらめな位置に円を 1 つ描くだけ

`draw()` は前のフレームの絵を消さない。消すには自分で `background()` を呼ぶ。このスケッチは呼ばないので、描いた円が全部残り、くり返すほど増えていく。「毎回消して描き直す」アニメーションと「描き足していく」絵の違いが、`background()` を呼ぶかどうかだけで決まる。

## 作り方

`draw()` の代わりに、共有の `autoplayLoop` で毎フレーム円を描き足す。1 秒に 60 個のペースは画面の書き換えの速さに左右されないよう、経った時間から描く数を決めている。画面の大きさが変わったら描き直すので、描いた円の位置は覚えておく（新しいほうから 4000 個。それより古い円は、上に重なった円で見えない）。座標は記事と同じ 500×100 のまま書き、表示の大きさに合わせて拡大している（`sketch.ts`）。

動きを減らす設定のときは描き足さず、300 個（5 秒分）を描いた絵で止める。

## もとのデモから変えたこと

記事の本文にはコードがなく、fiddle のコードがもと。違いは次のとおり。

- processing.js をやめて、canvas 2D で描いた
- 500×100 の固定の大きさをやめて、画面の大きさに合わせて同じ比のまま拡大・縮小するようにした（もとの 2 倍まで）
- 画面の外にある間とタブが裏にある間は止まる。動きを減らす設定では止まった絵になる
- 見出しは Google Fonts の Dancing Script を実行時に読んでいた。外から読まないよう、同梱の Molle にした
- Bootstrap 4 alpha の CSS と JS を読んでいたのをやめた。見出しの大きさと余白は自分で書いた
- 枠の点線は canvas ではなく、外の箱に付けた。canvas に付けると、描く大きさが線の分だけずれるため
